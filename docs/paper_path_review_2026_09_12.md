# ToolV2X：从当前实验到 CCF-B/C 论文的路径审查

日期：2026-09-12。用户目标是正式研究论文，会议或期刊均可，今年或明年均可；学校采用的具体 CCF 目录版本尚未确认。本报告是论文、公开实现和本地实验的对照分析，以及下一阶段建议，不是新方法已完成或录用概率评估。

## 1. 核心判断

**现有工作可以作为论文的实验基础，继续这轮共享驾驶适配有价值。但目前主要完成的是实验平台与能力适配，论文还缺一个可区分于近邻工作的具体方法贡献及其验证。**

复用 GoT、MTR、现成检测特征本身没有问题。对这个项目，更合理的目标是：已有可靠组件 + 一个与驾驶任务有关的协作机制 + 同条件对照 + 能解释的结果。原创性不要求每个模块从头设计，也不取决于工具数量或代码量。

一个可能成立的主线是：**根据当前任务需要，选择邻车的观测历史或预测结果，并决定是否继续获取证据，在轨迹质量、消息体积和计算代价之间取得更好的折中。** 这只是待验证的贡献候选；“工具调用”“按需通信”“轻量控制器”这些词本身已经不足以区分已有工作。

现阶段不建议同时展开新驾驶骨干、整套强化学习、RSU、第二种任务和闭环系统。先把现有底座上的一个问题做清楚；后续扩展应由所选主张的证据需要决定。

## 3. 对“实验和论文不完全一样”的处理

这里应把三种情况分清楚，不必追求所有工作都逐项复制一遍：

1. **组件复用**：采用原 MTR 网络、原 GoT 初始化，明确引用来源。我们的输入构造、任务和训练协议另行说明。
2. **基线适配**：为了同数据、同因果输入、同训练与推理预算比较，对参考方法进行必要修改，使用“某方法的适配版本”这样的名字。与原版差异列成一张表。
3. **原实验复现**：只有原数据划分、输入、任务、检查点和指标都对齐，才把结果称为原实验复现，并直接讨论原文数字是否重现。

当前 GoT-direct + P/F 属于前两类。可以成为研究论文的方法底座，但不能把这里的 ADE3 与其他论文的不同时间范围 L2、minADE6、不同数据划分或闭环 Driving Score 直接排成一个排行榜。

论文写作可使用这样的实现说明：

> 我们复用公开的 GoT 驾驶模型和 MTR 预测组件，并为两车按需协作构建统一接口。所有方法采用相同的因果观测、驾驶骨干和评价协议。与原 GoT 的多问推理设置不同，本实验使用直接轨迹输出；相关改动在实现细节中逐项列出。

这是对实验的准确说明，不需要把未使用的原模块重新实现出来以满足“百分之百一致”。

## 4. 最需要验证的研究增量

推荐优先研究**任务效用驱动的 P/F 交付方式选择**，先用有限动作空间形成强基线；是否进一步主张序贯获取，取决于真实的第二次决策增益。

这里必须正视当前 P/F 的特殊关系：完整 P 历史由接收方使用同一个 MTR 重算时，可以得到与 F 相同的预测。故差异需要拆成三部分：

- **信息量**：是否获得了原来没有的目标或历史，ROI 是否改变可用上下文。
- **计算位置**：预测由本车还是邻车执行，各自发生多少实际计算。
- **表达与入模容量**：历史和预测序列的长度不同，在固定上下文中保留的目标可能不同。

这使得“F 拥有本车永远不能得到的预测能力”不适合作为当前论文前提。反过来，**在相同来源信息下研究如何交付、在哪里计算，以及是否值得继续获取**，可以形成更准确的问题。但这是待证明的机会，不是已确认的新颖性。

**开始新机制之前的判断：** 在驾驶端充分适配之后，先检查 P/F 在质量、字节或计算代价上的相对优势是否随可观测场景变化。如果一个动作在目标预算范围内始终占优，就没有必要为了“选择”而再训练选择器。还要指出普通一次性选择器留下了什么具体问题；把同一个小分类器换个名称不构成另一项方法。

最小机制不必是复杂 RL。可以先在训练数据上生成有限动作的轨迹误差和实际成本，再建立一个只读取当前可用状态的一次性学习选择器，作为强基线。其监督必须来自训练部分；当前 108 个开发时刻的结果不能直接拿来训练后再在同一批时刻宣布有效。第一轮先与几何规则、固定动作和匹配预算的随机选择比较，只有发现明确局限并提出额外机制时，才增加新的方法与消融。

**尤其不要默认第二次调用必需。** 当前 `predict_p=True`：完整 P 到达后，本车已执行同一 MTR，因而同范围 F 可能只重复已有预测。首先确认第二次调用增加了什么，或改变了哪些可用上下文与表达；若没有增量，就不展开序贯学习。

如果主张“收到 P 后再决定是否调用 F”有价值，必须补充：

- 只看初始本车状态的一次选择，与看过实际 P 返回结果的第二次选择；
- 两者相同的总调用预算、可用能力和驾驶底座；
- P 已付出的通信及本地重算成本全部计入；
- 同 ROI、同目标范围的控制，避免把范围不同误当成顺序选择的优势。

固定 PF 与当前 Rule 的 P→F 并非天然同条件：前者默认全范围，后者查询前方 ROI。因此现在五方案结果可以发现现象，但还不足以独立证明序贯机制。

## 5. 一个克制但有研究说服力的实验包

下面按用途安排，既不是要求现在全部启动，也不是任何 CCF 等级的统一录用标准。

| 顺序 | 要回答的问题 | 最小证据与对照 | 为什么需要 |
| --- | --- | --- | --- |
| 1 | 驾驶底座能否合理生成轨迹、使用证据？ | 当前五条件生成；误差、格式失败、退化轨迹；恒速参考；逐录制组结果 | 让方法比较建立在可用基础上 |
| 2 | 通信收益是否只是挤占/释放上下文造成的？ | 保留 Ego-fixed；补充同总容量的 Ego-max 控制，说明其训练分布；必要时做匹配训练 | 当前为邻车固定预留 1536 token，不能把受限 Ego 写成最强纯本车基线 |
| 3 | 是否存在值得学习的选择问题？ | 当前固定/规则对照，加预算匹配随机、一个只看初始状态的学习选择器；额外机制提出后再与它比较 | 先建立强基线，不人为拆出多个名称相近的方法 |
| 4 | 新增机制的优势来自哪一项设计？ | 仅在提出额外机制后做对应关键消融；同信息本地重算；若主张序贯则加一次选择对照 | 每项消融对应一个具体主张 |
| 5 | 结果能否离开当前开发集？ | 冻结方法后用来源核实过的测试录制组；报告逐组配对结果与适当的不确定性 | 两个开发录制组不足以支持稳定泛化 |
| 6 | 为什么有些场景改善、另一些变差？ | 预先定义的场景分组和少量成功/失败图；通信质量—成本曲线 | 支撑机制解释和适用边界 |

预算曲线需要多个预算点，至少覆盖低、中、高开销。只比较固定 PF 与一种规则的两个点，只能支持该操作点下的比较。通信字节、token 数和计算时间应分别报告；本地实测时间也应与缓存命中、模型加载、网络传输的处理方式一起说明。

若把 P/F 的消息大小差异作为主贡献，还应统一数值精度和编码假设，防止优势只是某一种 JSON 写法造成的。实际 JSON 字节是当前实现的实测量；它不自动代表所有传输格式下的固有优势。

失败样本不能从结论中消失。当前评价已单列失败数和配对失败转换，ADE/FDE 仅对可解析轨迹计算。正式主表应同时展示失败率，另固定清楚的失败处理方案，避免方法通过更多无效输出获得更低的有效样本均值。

种子与数据扩展应花在关键处：驾驶底座固定后可先对小选择器重复训练，核对趋势；这只证明选择器层面的稳定性。若主张对驾驶初始化也稳定，再补驾驶种子/另一底座。邻近帧不是独立重复试验，应按录制组或时间块组织配对分析。两组开发数据不适合制造精确的“统计显著”结论。

关于第二数据集与闭环：它们取决于投稿方向与主张。专注开放环协作轨迹与成本的方法，首先需要可信的独立测试和机制分析；若写普遍场景泛化，多一个数据来源更有说服力；若写避碰能力、驾驶安全、车辆控制或真实时延，就需要相应的闭环或系统证据。不能把这些全部列成现在的并行任务，也不能提前承诺单数据集必然足够。

## 6. 当前结果出来以后，怎样组织论文

建议的研究问题是：**在给定通信与计算约束下，如何利用当前可见的驾驶状态，选择邻车的感知历史或预测结果，使本车未来轨迹更准确？** 如果序贯增益成立，再加入“如何利用已经返回的证据决定下一次查询”。

引言可以按四段推进：

1. 本车观测受遮挡限制，协作能提供额外信息，但通信与接收处理有成本。
2. 现有协作与工具方法已研究信息选择；本项目具体关注同一邻车不同交付形式的任务价值和计算代价，明确与最近工作的差别。
3. 说明我们提出的单一机制及其解决的具体困难，避免把复用的 MTR/GoT 写成原创模块。
4. 只在结果完成后填写主要发现、适用条件和实际贡献。

方法部分依次写任务与信息边界、P/F 服务、接收表示、选择与停止机制、训练方式。实验部分依次回答基础质量、总体质量—成本、机制消融、独立组结果和失败案例。完整实现表、原框架差异、数据来源和额外案例放附录。

建议准备四张主图/表：

- **框架图**：以一种清楚标识显示复用模块，以另一种标识显示我们新增的方法。
- **主要对照表**：统一数据/底座/预算下的轨迹误差、失败率、字节、计算开销。
- **质量—成本曲线与关键消融**：证明提出的机制比固定或简单选择更划算。
- **同场景对照图**：本车/邻车证据、目标轨迹、不同方法输出；包含失败案例。

论文主张跟随结果选择，不能在数值出来后改变评价口径：

| 观察到的结果 | 合理的论文方向 | 仍要补的证明 |
| --- | --- | --- |
| 固定 F 已经改善轨迹，但还没超过它的选择方法 | 证明 F 适配和协作底座可用，作为基础实验 | 继续寻找具体机制价值；仅此不足以把工具选择写成主贡献 |
| 选择方法保持接近固定最佳方案的质量，减少通信/计算 | 按需协作与效率折中 | 预先定义“接近”的容忍度、多个预算点、强规则/随机/小学习基线 |
| 一部分可解释场景收益明显，整体平均改善较小 | 特定条件下的协作决策或减少负面协作 | 用可观测条件定义分组，并在独立数据复核，不能只挑好看的帧 |
| 顺序选择没有优于一次选择 | 将论文主张收敛为一次交付方式选择（若该贡献仍成立） | 不为保留 Tool/Agent 名字硬加循环 |
| 充分适配后，各通信方案都很弱或一种动作处处占优 | 先诊断表示、能力质量与任务敏感性，再判断是否调整研究问题 | 不能靠继续堆路由机制或只换措辞解决 |

贡献表述可以采用“定义问题并给出公平接口、提出一个具体选择机制、在独立协议上验证其质量—成本效果”的结构，但前一项不应夸成新的通用基准，后一项必须等真实结果。标题和摘要中的数值、‘显著’、‘安全’和‘泛化’等表述全部留到证据确定后。

## 7. 需要提前处理、但不必无限扩大的事项

**预训练来源与测试独立性。** 下游按录制组隔离不自动说明原检测器、MTR 初始化或 GoT 初始化从未见过这些片段。现有 manifest 已记录这一边界。优先核实公开训练清单与已有权重来源，再确定正式测试集合；若来源无法澄清，当前结果可以保留为固定缓存下的受控实验，但对未见场景的结论需要新的独立证据。

**P/F 同信息与上下文截断。** 通信报文与真正进入模型的对象不是同一层面。报告字节和完整响应时，还要记录保留/丢弃对象与本车输入容量。让框架准确，是避免后面返工的必要工作；这些日志和测试通常进入复现材料，不应占据主要贡献篇幅。

**参考方法的复现范围。** 一个能浏览的仓库、一个 demo、训练代码和全套论文评估不是同一件事。对不完整的公开实现，记录已核实模块与缺项；如果需要适配基线，按明确新协议实现并命名，不推测作者的内部实验。

## 10. 审查后的取舍记录

主 agent 对三组报告的复核收紧了以下判断：完整 P 默认已经在本地生成预测，不能预设 P→F 的增量；一个一次性小选择器先作为强基线，不能同时换名充当多个方法；与一次选择有相同终态动作集时，两步离线 oracle 可以具有相同上界，在线结果条件化是否有用要比较在线策略，不能用“两步 oracle 必须更强”作必要条件；第二数据源、闭环、校准和安全指标均由具体主张触发。

**后续执行以本主报告的收缩判断为准。** 各附录提供文献证据和可选思路，不是把其中所有候选实验同时加入任务清单。现在首先交付当前五方案结果，并据其解释决定一项研究增量。
