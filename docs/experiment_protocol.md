## 1. 当前结论与实验层级

**准备产物可以继续使用；现有四个 CMP YAML 尚不具备启动正式 ToolV2X 训练的条件。**

- 已完成：六份世界系跟踪产物检查；采集记录分组隔离；独立决策帧 manifest；因果历史窗口；历史 oracle 的明确缺陷修正。
- 历史诊断：原 CMP 使用 GT 身份辅助、future-valid 目标筛选、移动坐标轨迹及 BEV 补零。可用于兼容性检查，但正负结果均不能决定因果 P/F 路由方向是否成立。
- 因果能力探查：使用本规范的窗口和接收器，先比较消息价值。尚待接入预测器，不能把窗口生成 PASS 写成预测实验 PASS。

## 2. 数据划分与独立评价集合

可执行入口：`src/common/audit_protocol.py`。产物在 `outputs/protocol_audit/`。

1. 以 `testoutput_CAV_data_YYYY-MM-DD-HH-MM-SS` 为采集记录组；尾部片段编号不构成独立记录。
2. 保留原 test 的 9 个片段，训练侧与其同记录的 15 个片段全部隔离。
3. 剩余记录按名称时间排序，最后 2 个记录留为验证；得到 train 15、validation 2、test 9 个片段。
4. 精确执行名单见 `split_manifest.json`。train/validation 都从磁盘源 split `train` 读取，禁止将整个窗口 train 目录直接当训练集。
5. 决策帧只由场景长度与时域定义：局部 t 从 10 到 T−51，历史 11 帧、预测未来 50 帧、10 Hz。不得用任何目标是否在未来持续标注/检测成功来筛决策帧或在线目标。
6. 当前决策帧数量：train 3027、validation 108、test 1453；窗口缓存还包含末尾 50 帧，用于在线输入完整性检查，正式评价只取 manifest。
7. GT future validity 只影响对应离线监督/评价掩码。没有标签不代表没有障碍，不得据此从在线输入删掉目标。

真实位姿检查：平移邻域 0.001 m、4×4 矩阵绝对容差 0.0001、相对容差 0；发现 147 对 train/test 重复，隔离后残留 0。
这是位姿与记录分组检查，不证明路段或所有传感器内容独立。

**上游限制**：已有检测结果来自预训练检测器。新划分不能逆转已有权重的训练历史。正式留出结论前，核实检测器训练记录；不能证明独立时，按隔离后的 train 重训检测器并重导出检测/跟踪。旧缓存结果标为固定感知缓存诊断，不冒充完整未见场景评估。

## 3. 因果输入契约

入口：`src/prediction/causal_windows.py`；产物：`outputs/causal_windows_v1/{source_split}/{source}/{scene}.pkl`。

- 输入是已有 `outputs/tracks/{train,test}/{config}_world.pkl`，来源限 ego 单车、CAV1 单车、CoBEVT 三种。
- 对每个决策 t，只读取 `[t−10,t]` 跟踪观测及 ego 在 t 的位姿。
- 全窗口统一变换到 **ego(t)**，位置米、角度弧度、时间步长 **0.1 s**；不得把每帧 ego 坐标系当作同一个固定系。
- `states: [N,11,7]` = x,y,z,l,w,h,yaw；`valid: [N,11]`、`scores: [N,11]` 分离。
- 不读 GT，不按 GT 身份合并/删除检测轨迹，不使用未来观测插值。
- 目标集合为 t 时刻 tracker 输出；保留全部目标和缺失掩码。`eligible` 表示历史至少 2 个有效状态，只能决定能否调用某预测器；不合格目标必须保留并使用明确标注的静止/恒速回退，不得当作空道路。
- IDs 是来源内的 tracker ID。跨来源用 `(source, track_id)` 命名，匹配依赖 t 时刻几何/历史，不允许把 GT ID 当作通信字段。
- manifest 中的场景名和长度属于离线索引元数据。窗口导出本身不读取 GT pickle。
- `native_cmp_ready=False` 是明确接口边界：不能把这些数据改名后直接喂给旧 CMP dataset。

回归要求：增加/扰动 t 之后的帧不得改变 t 的输入；删除 GT 文件读取能力仍能构造窗口；缺洞保持 masked；CAV1-only 目标能够独立出现在 CAV1 窗口中。

## 4. 四动作与接收器

当前已有缓存能定义的能力探查：

| 动作 | 可用感知历史 | 远端预测响应 | 接收器要求 |
|---|---|---|---|
| STOP / Ego | ego 单车 | 无 | 本地预测 + 明确的短历史回退 |
| P | CoBEVT 协作感知缓存 | 无 | 本地预测；此时的 P 是协作感知服务替身 |
| F | ego 单车 | CAV1 因果预测 | 本地与远端目标并集，包括远端独有目标 |
| PF | CoBEVT 协作感知缓存 | 同一份 CAV1 因果预测 | 同一接收器规则、同一去重逻辑 |

这张表是缓存能力比较，不能声称已经实现真实 P 服务。

必须显式解决的历史成本：当前 CoBEVT 跟踪包含历史协作信息。不能仅按 t 时刻的一条 P 消息计费，却免费使用过去协作历史。正式接口需选择并固定：一次付费获取完整历史响应，或连续回放并记录过去调用、缓存和消息的成本。STOP/F 不能读预先计算的 CoBEVT 历史。

F 在 F/PF 两个动作下使用同一远端预测器、同一原始历史、同一参数与输出，避免把两套模型差异当作“是否调 P”的作用。ego/P 侧预测器优先共享参数或采用混合来源训练并保留独立模型诊断；不得把分别训练四个模型的偶然差异全解释为路由价值。

**现有 CMP 聚合器不满足上表**：`MotionAggregatorTransformer.forward` 只迭代 ego 的 `center_objects_id`，输出数量被强制等于 ego 目标数。它能调整共同目标的预测，但不输出远端独有目标。还依赖 GT 对齐后的身份和 BEV 支路；补零后只是修改版，不能称 CMP 完整复现。

最小接收器实现要求：独立导出 ego/peer 预测；在 t 时刻做几何匹配；匹配目标用预先固定的规则合并，未匹配 peer 目标必须保留。先用简单规则，不能为打通数据额外引入可训练 Transformer。原 CMP 聚合器作为共同目标细化对照保留。

同信息强对照：远端当前/历史状态传回后，由本地同规格预测器计算 F，并完整计入传输和本地计算；用于区分远端信息、模型能力和计算委托的收益。实际 P/F 响应 schema 在实现时逐字段固定，不能只用服务名称宣称信息等价。

## 5. 预测模型接入前的检查

1. 使用因果窗口中的在线 ID/目标列表，GT 只通过单独的离线监督匹配产生 label 与 loss mask。
2. 移除旧 dataset 的 GT-key 交集筛选、future-valid 在线目标筛选、整段插值；正确处理空目标帧和不完整历史。
3. 单个样本的历史及 future label 都在 ego(t) 或固定世界系表达，不能混合移动 ego 系。
4. 时间编码使用 0.1 s。旧 CMP `0.1 * (0.1 * i)` 是 0.01 s；已修正的数据不能直接假定适配旧权重。
5. 对预测导出要求 `status=ok/empty/error` 的逐帧记录；“模型返回合法空集”与“文件没生成”必须可区分。每帧还要记录输入目标、eligible、回退目标和实际预测目标，核对覆盖。
6. 有多个评估目录时必须明确选择，不允许拿 glob 的第一项。
7. 验证现存权重的输入约定和输出数值后再决定重用/微调/重训。权重文件存在不等于可用，环境依赖缺失也不等于研究不可行。

上述接入未完成。本轮没有修改 CMP 模型结构或宣称修复其完整 dataset；不通过设置一个 PASS 标志绕过检查。

## 6. 规划评价与允许的结论

历史入口 `src/oracle/oracle_analysis.py` 现在要求：

- 显式 `--protocol legacy-gt-reference-diagnostic` 和独立 `--frames_json`。
- 四动作覆盖恰好等于 manifest，不取交集掩盖缺帧；非法、缺时域、非有限轨迹或非法概率报错。
- 只排除 ego 自身。CAV1 是物理障碍，不能因合作身份而排除。
- GT ego 身份识别当前仍采用原点 1.5m 启发式；多个候选报错。正式接收器必须用非 GT 的 ego footprint/传感器自车过滤，不将这段诊断逻辑搬入在线输入。
- 给定 GT 未来参考路径，只选择纵向速度；标题、报告均标明是 GT 条件诊断。
- 当前中心距 <2.5m 只称 observed proximity，不称车体碰撞或闭环安全；同时报告 GT 观测覆盖，未观测部分不能算安全。
- quality = 与 GT 条件速度规划 waypoint L2 + 10 × proximity，是诊断效用，不是通信成本；这套指标不能替代真实参考轨迹偏差、进度、舒适性和几何碰撞指标。
- 多动作接近时报告“无唯一严格最优”，不能解释成“四者全相同”；0.05 仅为描述性差距，不是方向门槛。
- 缺少实测 cost ledger 时，不生成通信节省百分比或 Pareto 宣称。

正式因果能力探查使用独立输入/输出 ledger 和非 GT 身份接收器。保留 GT 路径受控实验作为一个明确上界设定，另行加入时间 t 可得的路线/历史外推参考路径对照，才能讨论可部署性。

## 7. 成本、统计和继续条件

成本 ledger 每个帧/动作至少记录：请求/响应字节、序列化格式、压缩方式、额外身份/位姿/置信度字段、获取历史的成本、本地/远端计算时间、等待时间、缓存来源、错误/超时状态。PF 是否共享字段或计算必须来自实际调用记录，不默认等于 P+F。缺测写 null，不写 0。

报告流程：

1. 先报告四固定策略与逐帧质量 oracle，检查远端信息是否有增益、远端独有目标是否真正到达规划输入。
2. 报告质量—实测字节曲线，延迟作为独立维度；权重/约束在验证集预先选择。近等质量下按成本选动作，明确定义并列最优规则。
3. 统计以采集记录为重采样单位，保留四动作同帧配对，不能把连续帧当独立样本。报告逐记录结果、均值和配对 bootstrap 区间；当前 test 仅 6 个记录组，区间不稳定需如实说明。
4. 去掉“P/F 严格最优占比 10–15%”停止线。继续条件是稳定的质量收益或给定质量容忍范围内的成本节省；容忍范围在验证集固定，不能看 test 调整。
5. 然后训练只读 t 时刻特征的规则/小模型路由；验证能否实现 oracle 收益。GT oracle标签仅用于监督，不进在线特征。
6. 若小模型通过，再考虑 LLM hidden state。顺序路由需相同预算、接收器和划分下比较 `s0` 与 `s0+P响应` 的选择能力；新增目标数量相关性不构成必要性证明。
