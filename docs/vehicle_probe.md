# 车车 P/F 最小接口验证

> 后续进展：共享学习型基线与两个验证场景的结果已完成，见 [learned_capability.md](learned_capability.md)。本文保留第一轮恒速接口验证的原始结果。

日期：2026-09-10。用户最新范围：继续已有车车工作，RSU 以后再考虑。

**结论：单场景接口验证已跑通；没有获得规划收益或路由有效性的证据。**
本次把独立 ego/CAV1 预测、消息序列化、目标接收和离线评分实际连起来。没有继续绑定 CMP 聚合器。

## 1. 本次到底运行了什么

- 选择规则：取既定 validation manifest 按名称排序的第一个场景，不依据结果挑选。
- 场景：`testoutput_CAV_data_2022-03-17-16-06-11_0`。原物理 split 是 train，实验角色是 validation。
- 局部 t=10..69，共 60 个决策帧；决策集合来自此前独立 manifest。
- 输入：ego 与 CAV1 单车检测产生的世界系跟踪，经上一轮因果窗口转换到 ego(t)。没有读取 CoBEVT 分支。
- 预测器：在过去 1 秒有效位置上做线性拟合，得到恒速，外推未来 5 秒；历史不足两个有效点时保留目标并作静止回退。
- 参考路径：只用 ego 过去 1 秒位姿估计速度并外推 3 秒；没有使用 GT 未来路线。速度选择仍是瞬时比例缩放，并非有动力学约束的车辆规划器。
- 形式：冻结观测截止时刻 t 的离线反事实枚举，每帧运行 Ego、P、F、PF。没有在线路由策略。
- 真实执行的是 NumPy/SciPy 恒速计算与本进程 JSON 编解码；不是学习型 MTR、VLM 推理、网络服务部署或闭环仿真。
- 未加入 RSU、I 自身计划、LLM、RL；没有启动训练、下载权重或改造 CMP 模型。

## 2. 本次 P/F 是明确的同信息对照

这里 **P = P_history**：远端返回当前在跟踪的目标及其完整 1 秒历史、mask、分数、来源内 ID。
这里 **F = F_cv**：远端使用上述同一份历史计算 5 秒恒速预测，并返回当前框、轨迹、置信度和回退标记。

P 在本地经过同一预测算法后，应与 F 完全相同。这是刻意设置的正确性对照：验证计算放在发送端或接收端不会凭空改变信息和预测。它不是已经确定的最终 P/F 服务设计，也不能据此判定所有预测服务都无价值。

相对旧 CoBEVT-P 缓存，本次 P 是独立 CAV1 历史响应，没有免费引入历史协作感知。消息中传送完整有效/缺失历史；当前窗口所有历史信息均在应用层响应字节中计入。

请求范围固定为全部当前 peer tracks，没有根据 GT 选 ROI/目标，也没有学习查询范围。请求携带当前 ego 位姿，双方共用 ego(t) 坐标系。未模拟消息到达时的状态变化。

## 3. 接收器行为

- ego 与 peer 的 tracker ID 分别命名，整数相同不等于同一个物体。
- 使用当前中心距的 Hungarian 一对一匹配，阈值 2m；共同目标的预测取简单平均，未匹配的远端目标全部保留。
- 仅按当前 ego 原点 1.5m 范围做自车过滤，不读取 GT 身份；合作车不会因身份而被排除。
- PF 中同一 peer 只计入一次；P/F 的来源、时间和当前目标框不一致时报错。
- 正常空响应、缺失响应、非有限数值、错误时间/来源均按接口规则区分，不用取四配置交集来隐藏缺帧。
- 上述距离匹配和自车中心过滤仍是启发式，可能误配相邻目标。离线“peer-only”表示当前规则下未匹配 ego 目标，不等于物理遮挡真值。

## 4. 实际结果

- 60/60 帧保留了远端未匹配目标，累计 828 条目标-帧记录，平均每帧 13.8 条；不是 828 个独立物体。
- P 的本地预测与 F 的远端预测在 60/60 帧完全相同。
- P、F、PF 的接收目标、融合预测和速度选择在 60/60 帧完全相同。
- 四种策略在全部 60 帧都选择 1.0 倍参考速度，均存在该代理规则下的无冲突候选。

| 动作 | 每帧规划输入目标 | 每帧当前 GT 几何匹配目标 | 3s ego 平均 L2 (m) | 已观测近距离事件比例 | 每帧应用层请求+响应字节 |
|---|---:|---:|---:|---:|---:|
| ego | 24.98 | 24.33 | 0.7244 | 0.0000 | 0.0 |
| P | 38.78 | 36.28 | 0.7244 | 0.0000 | 45665.7 |
| F | 38.78 | 36.28 | 0.7244 | 0.0000 | 60630.6 |
| PF | 38.78 | 36.28 | 0.7244 | 0.0000 | 106296.3 |

这组数据没有显示规划收益。不能将它作为协作/序贯路由 NO-GO：这里只是一个预先选定场景、简单恒速能力及直线外推参考，不是充分的机制检验。

应用层字节来自实际写入 messages.jsonl 的紧凑 UTF-8 JSON 字符串逐条计数。本格式下 F 比 P_history 大；不能把 F 默认设成“更省通信”。PF 发出两个独立请求与响应，所以本次计数确实等于两者之和，这不是对未来协议的普遍假设。

无物理网络；网络时延、上游检测/跟踪计算成本均为 null。记录的 sender_processing_ms 与 receiver_planning_ms 是当前 Python 进程的单次墙钟时间，不能当车端延迟基准。枚举所有动作产生了额外探查计算，尚未运行只执行所选动作的真实策略。

## 5. 独立评价边界

GT 只在生成决策完成后的 `evaluate_vehicle_probe.py` 中读取，用于目标匹配、预测误差及规划代理评分。

- 目标关联：预测当前框与 GT 当前框做几何一对一匹配，未来 GT 按离线身份关联，缺失时间 masked；不会改变在线目标集合。
- 已观测近距离事件 = 任一已标注未来目标中心与 ego 候选中心距小于 2.5m。它不是车体碰撞率，也不是闭环安全结论。
- GT_future_coverage 在逐帧 CSV 中记录，缺标不能解释为安全。
- 原始评分中保留 observed ADE/FDE 供诊断。Ego 与协作输入的匹配目标集合不同，不能直接用两个均值之差宣称预测精度提升；需要共同目标集合的配对指标和新增目标覆盖分开报告。
- 缓存检测器训练来源仍未核实，此处没有完整未见场景泛化声明。

## 6. 验证与可追溯产物

目录：`outputs/vehicle_probe_v1/testoutput_CAV_data_2022-03-17-16-06-11_0/`。

- `run.json`：场景角色、决策帧、输入路径、算法和实验边界。
- `messages.jsonl`：每次请求/响应的实际字符串、字节、已测量和未知的成本字段。
- `decisions.jsonl`：独立 ego 预测、因果参考路径、四动作接收目标和规划输出。
- `generation_input_guard.json`：生成时禁用 GT 读取、GT ego 未来函数及权重读取的检查记录。
- `generation_summary.json`：覆盖与一致性计数。
- `offline_per_frame.csv` / `offline_summary.json`：单独的离线 GT 评分。
- `artifact_verification.json`：独立多项式拟合复算预测、来源目标完整性、消息字节和因果参考的复核结果。
- `code_snapshot/`：本次源码与检查脚本副本，无需依赖后续工作区版本猜测实验行为。
