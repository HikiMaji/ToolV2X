### 1. 最重要的新问题：五策略训练可能在“重复终态”上隐式重加权

当前训练导出是每个训练帧分别加入 `Ego/P/F/PF/rule` 五条样本；训练器也是按 sample 内这些行随机排列，并不会按最终实际 prompt 去重。

但你的驾驶 prompt **不包含 policy 名字**，真正送给模型的是固定本车块 + 已购邻车块。

于是可能出现：

* `rule` 最终 P→F，与某些 PF 终态事实上完全相同；
* `rule` P 后停止，与 P 相同；
* `rule` 直接停止，与 Ego 相同。

小样本联调里 rule 已经是 **17/20 P→F，1/20 P-stop，2/20 direct-stop**。

也就是说，虽然表面上“五策略各占 20%”，**实际输入分布可能把 PF 类证据重复训练了近两遍**。这不会造成数据泄漏，但会影响共享驾驶器的学习分布，使之后的策略公平比较多一个混杂变量。

我建议全量 episode 完成后、正式解释训练结果前，先计算：

> 同一个 frame 内，五策略最终 `q9_prompt` 的 exact duplicate / canonical duplicate 比例。

如果重复显著，最干净的方法是**按唯一最终驾驶输入训练一次**，或者对重复 prompt 做 inverse-frequency weighting。至少做一个“原五策略平衡 vs 唯一证据状态平衡”的消融。

这个问题我认为比继续多加几个策略更值得优先解决。

### 2. 当前 Ego 对照公平，但不是最强 Ego baseline

`context.py` 为了保证五策略的本车块完全一样，固定给远端证据预留 **1536 tokens**：

```text
context = 4096
generation reserve = 256
peer reserve = 1536
```

而这个 reserve **即使 Ego 根本不会查询邻车也存在**。

这在做“P/F 是否在相同本车信息基础上增加价值”时非常好，因为不会出现 F 得到了不同 Ego 对象的问题。

但代价是：**Ego-only 被主动限制了本地证据容量。**

联调结果已经表现为本车平均只保留 **2.65 条记录**。

所以最终论文/主实验里，我建议保留现在这个：

* `Ego-fixed-budget`：与你所有工具策略共享完全相同 local block，作为**因果归因基线**。

再增加一个：

* `Ego-max-context`：没有远端查询时，让 Ego 使用整个可用 4096 上下文（仍保留 generation reserve）。

这样可以回答两个不同问题：

$$
\text{工具增益} =
P/F - Ego_{\text{fixed}}
$$

以及

$$
\text{在固定总上下文预算下，远端证据是否值得挤掉本地证据？}
=
P/F - Ego_{\text{max}}
$$

如果不加第二项，未来 P/F 胜过 Ego 时，审稿人完全可以问：

> 为什么 Ego 明明不用通信，却还必须白白留 1536 token 给不存在的 peer？

这不会否定你现在的设计，但需要一个强 baseline 把这个解释堵住。

### 现在最应该盯的是“驾驶模型有没有真正学会”，不是 P/F 谁赢

这次小样本联调里：

| 策略            |        ADE3 |
| ------------- | ----------: |
| Ego           |    13.014 m |
| P             |    15.520 m |
| F             |    12.639 m |
| PF            |    13.086 m |
| rule          |    29.451 m |
| **简单零转向纵向外推** | **1.175 m** |

这是只有 4 个验证帧的联调，**绝对不能拿来比较策略**。

但它给出了一个非常明确的 sanity gate：

> **正式适配后的共享驾驶模型，至少应该先大幅缩小与简单运动外推之间的差距。**

如果全量 2987 帧训练后，GoT 仍然十几米 ADE，而简单运动学基线是一两米，那么这时候不应该去训练 router。

应该先查：

1. direct 轨迹任务是否和原 GoT 的输出分布严重错配；
2. point feature / text evidence 是否被真正利用；
3. 模仿标签的尺度与模型输出先验；
4. LoRA + projector 是否足以适配；
5. 是否需要 residual trajectory 参数化，而不是让 LLM 从零生成绝对 `(x,y)`。

尤其第五项值得记住：如果模型总爱生成几十米的位置，后续可以考虑让模型输出

$$
\Delta \mathbf{x}_{LLM}
$$

并以简单运动学 trajectory 为 reference：

$$
\hat{\mathbf{x}}_t
=
\mathbf{x}^{CV}_t + \Delta\mathbf{x}_t
$$

但**现在还不建议改**。先看这次完整 SFT 到底能不能把问题学下来。
