# Ego / 固定 F 配对驾驶样本

日期：2026-09-11。**第一步已完成：3095 帧真实 Ego/F 证据，5974 条训练样本和 216 条验证输入均已落盘并核对。** 本次准备同一个驾驶模型可使用的两种输入；没有更新驾驶参数或生成驾驶轨迹。

## 本步解决的问题

要比较加入邻车预测后的变化，Ego 与 F 条件中的本车特征、运动状态、本车文字证据必须相同。旧流程将两源目标合并排序，F 可能挤掉本车记录；compact 的共享字段也会随远端目标改变。本次先固定并落盘 Ego，再实际查询 F，将邻车证据作为独立文本块追加到任务指令之前。

沿用已有 GoT 两帧浅层检测特征及原 tokenizer/提示模板，保留已实现的直接六点轨迹任务。冻结后的 CMP 原 MTR 为本车和邻车的观测目标生成预测。**F 中的目标预测属于驾驶输入；自车未来六点属于独立离线监督，是下一步驾驶器要学习输出的内容。**

## 数据范围

| 用途 | 原候选帧 | 保留帧 | 停用帧 | 录制组 |
|---|---:|---:|---:|---:|
| 训练 | 3027 | 2987 | 40 | 8 |
| 开发验证 | 108 | 108 | 0 | 2 |

每个保留帧对应 Ego/F 两种条件，训练导出 2987×2=5974 条同标签样本；验证导出 108×2=216 条不含答案的输入。四个训练帧的 F 未返回观测目标，仍完整保留；有远端返回却全部被截断的帧数为 0。

沿用既有录制组划分，不读取测试输入或测试标签。对这些片段的相邻 Ego pose 使用已记录的大于 20 米平移或 20 度航向变化阈值，只发现既知的 g2760→2761、67.34 米跳变。历史一秒或标签未来三秒跨断点的窗口统一停用，全部理由保存在 `continuity.json`；原数据、旧实验与冻结 MTR 均保留。

## 固定选择及其代价

- 总上下文 4096 token；预留轨迹生成 256、邻车块 1536。本车提示连同实际两帧特征 token 最多 2304。仅按当前目标锚点距离选择完整记录，六模态和各自分数均保留，沿用两位小数。
- Ego 条件在查询前完成，只读本车，远端调用及报文字节均为零。F 条件实际调用一次邻车预测服务，读取该源完整因果上下文，保留完整原数组、报文和入模记录；未入模目标也记录，不等同于完整覆盖。
- F 服务在本机按来源隔离执行，成本中的字节数来自真实序列化报文；没有测量车联网传输时延。
- 两条件使用同一个本车特征文件和完全相同的本车文字块。预留空间限制了 Ego 的文字容量，因此本轮是固定本车输入的条件对照，不能把它当作充分优化后的独立 Ego 基线。
- 不提前读取远端内容来决定保留哪些本车目标。没有返回目标或返回后入模为空的样本也保留；不因协同信息少而筛掉样本。

MTR 在 GPU 上按最多 32 个目标成批执行，每个目标仍使用原完整场景上下文。首个真实帧与已有 CPU 单目标参考执行比较，预测坐标最大绝对差约 0.000153 米、分数约 2.57e-7，通过预定容差；此项只核对本次执行优化，不证明原生 CUDA 算子一致性。

## 实际覆盖与验证

以下为逐帧源内目标记录数的平均值，同一个物理目标可能同时被两车观察，不能将两列相加当作独立车辆数。

| 用途 | 本车完整 / 入模 | 邻车完整 / 入模 |
|---|---:|---:|
| 训练 | 10.37 / 2.49 | 10.41 / 2.96 |
| 开发验证 | 19.28 / 2.97 | 20.91 / 2.57 |

文字容量仍有限。当前保留此固定版本进入驾驶适配；若 F 没有改善，须结合覆盖记录解释，不能直接外推为邻车预测没有价值。本轮没有通过删除模态或粗化数值扩大容量。

所有 Ego 提示含特征的长度均不超过 2304，F 条件最大为 3840，加上 256 生成预算恰好不超过 4096。全部 3095 帧的原生标签重新计算一致、保存的本车数组与原缓存逐元素一致；5974 条训练行的有效损失标签均仅为 assistant 答案及结束符。

## 产物

运行目录：`outputs/paired_driving_data_v1/`。

- `online_index/` 与 `continuity.json`：原划分下的保留样本、逐帧因果输入引用及完整停用理由。
- `frames/`：每帧共享本车特征、两源 MTR 原输出、Ego/F 提示、F 原始报文和执行记录。
- `offline_labels/`、`examples/train.jsonl`、`evaluation/validation.jsonl`：已由独立离线进程连接标签并导出；验证输入不包含目标答案。
- `coverage.json`、`preparation_result.json`：最终逐帧覆盖、token 和成本记录，以及完成范围。
- `verify_export.py`、`export_verification.json`：标准库独立核对已导出文件的配对、共用输入、同标签、训练/验证分离、停用清单与计数，结果 PASS。

代码的四项新检查、完整 101 项测试和轻量 75 项检查均通过，日志保存在运行目录。在线物化及离线导出过程均正常退出；在线物化约 858 秒，另有首帧 CPU 参考执行核对。检查通过只表示这一版数据构造和接口条件成立。

实现为 [在线物化](../src/planning/paired_inputs.py) 和 [离线准备/导出](../scripts/prepare_paired_driving.py)，复用既有工具、MTR、原标签及监督编码接口。完整运行命令见 [开发日志](dev_log.md) 中本轮运行说明。

## 后续使用和论文边界

配对训练行用于下一步共享驾驶适配；同帧记录、原输出和成本可用于后续 P 条件及调用价值分析。本步支持说明数据构造、输入隔离和公平对照设置，尚无驾驶误差或协同收益结论。

开发验证录制组已参与过选模；实际传感器时间、上游预训练来源与冻结 MTR 既往训练限制保留。窗口隔离不等于完成原始数据修复或完整 CMP 复现。
