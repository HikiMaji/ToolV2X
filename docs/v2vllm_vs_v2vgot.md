# V2V-LLM 与 V2V-GoT：当前任务端应该选什么

核对日期：2026-09-11。此次只核查论文、本地代码、训练脚本和权重文件，没有更换当前实现、运行新模型或启动训练。

## 判断

如果继续使用“速度/转向分类 → 六点轨迹”的两阶段任务，现有 GoT 权重更贴合其原训练任务。若为 ToolV2X 选择主任务骨干，我更倾向 V2V-LLM 式直接规划：接收 Ego 特征及已经取得的 P/F 证据，直接生成轨迹，把 Q8 作为待验证的辅助任务或解码消融。这个判断针对项目机制匹配，不等于已证明 V2V-LLM 权重在当前输入上更准确。

当前实际复用的是 GoT 仓库的模型实现、权重和 Q8→Q9 任务链，未执行其 Q1–Q7 图推理。只凭目前的两节点链条，不能声称沿用了完整 GoT 机制。

## 论文任务不能按末两题直接对应

| 项目 | V2V-LLM | V2V-GoT | 当前 ToolV2X |
|---|---|---|---|
| 任务组织 | Q1–Q3 grounding、Q4 关键目标识别、Q5 规划 | Q1–Q4 感知、Q5–Q7 预测、Q8 动作分类、Q9 轨迹 | 工具提供结构化 P/F，驾驶端执行 Q8→Q9 |
| 最终输出 | Q5：未来 3 秒的六点轨迹 | Q9：未来 3 秒的六点轨迹 | 相同六点输出定义 |
| 推理依赖 | 规划任务可直接回答轨迹 | Q7 预测作为 Q8 上下文，生成的 Q8 作为 Q9 上下文 | Q1–Q7 未运行，改为输入实际取得的工具证据 |

上述任务定义见 [V2V-LLM §3.3](https://arxiv.org/html/2502.09980v3#S3.SS3) 和 [V2V-GoT §III-F](https://arxiv.org/html/2509.18053v4#S3.SS6)。V2V-LLM 的 Q4 是关键目标识别，不是 GoT 的 Q8 动作分类；两篇论文的直接终端对应是 Q5 与 Q9。

GoT 正文将 V2V-LLM 的基线也扩展为当前和前一时刻输入，使用同一最终规划任务进行比较。因此不能简单把两者区别概括为“LLM 单帧、GoT 多帧”；本地恰好已有该两帧 V2V-LLM 版本。[GoT §V-A](https://arxiv.org/html/2509.18053v4#S5.SS1)

GoT 论文中更好的规划指标来自其完整设置；文中的简化图实验还重新训练了对应上下文的数据。这不支持把完整图收益直接移植到当前省略 Q1–Q7 的系统。[GoT §V-C](https://arxiv.org/html/2509.18053v4#S5.SS3)

- 本机已有 `v2vllmq5_10ep_both_shallow_f2/checkpoint-490`，以及 `v2vllmq5_10ep_both_shallow_f2_ego_only/checkpoint-2695`。adapter、非 LoRA 可训练权重和配置文件均存在，无需新下载。
- GoT 与两帧 V2V-LLM 的本地配置同属 LLaVA 7B，hidden size 4096、scene projector 输入 3072，LoRA rank 128 / alpha 256。架构配置相近，不代表权重质量、训练样本或输入分布相同。
- 原两帧 V2V-LLM 训练脚本只读取 `v2v4real_3d_grounding_qa_dataset_v2vllmq5.json`；本地该文件有 12,290 条训练 QA。抽查样本为直接询问未来轨迹并回答六点，没有 Q8 父回答。把这个规划权重直接接到当前强制 Q8→Q9 的入口，仍会改变其训练任务形式。
- 本次文件和脚本检查没有证明两帧 V2V-LLM 或 ego-only 权重在 ToolV2X 上的质量；也没有消除这些发布权重的训练来源限制。

权重共同目录：`/root/autodl-tmp/V2V-GoT/LLaVA/checkpoints/llava-v1.5-7b-task-lora/`；完整模型目录前缀均为 `llava-v1.5-7b-task-lora_v2v4real_3d_grounding_`。

## 建议的下一步

先确定任务接口与初始化，之后再全量适配驾驶模型。小规模对照应区分两个因素：GoT / V2V-LLM 初始化，以及直接轨迹 / Q8→轨迹解码。两种解码方式都需要用对应训练样本适配，不能拿任务分布不同的零样本结果直接判定哪种骨干更好。

比较时固定 Ego 特征、P/F 证据、训练/验证录制组与可比较的微调预算，报告轨迹误差、生成失败和总推理代价；所有查询策略最终共用选定且冻结的驾驶模型。Q8 只有在带来稳定任务收益或明确监督价值时才保留为必经步骤。

V2V-LLM 原设置也会先汇入多车感知特征，不能直接恢复该默认输入方式；ToolV2X 仍需保持“Ego 信息先可见，远端信息调用后才可见”的约束。建议复用其规划模型和任务定义，保留现有工具边界。

已完成的 MTR 适配、P/F 协议、因果窗口和评价代码可以继续使用。完整 GoT 更适合作为固定图推理的对照方向；其涉及未来计划的输入仍需先核实时间因果性，不能直接用 GT 未来来比较在线收益。
