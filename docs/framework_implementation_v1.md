# ToolV2X 完整运行基线：实现与验证

2026-09-11。用户已在整体框架修订后要求“开始进行”，本文件将已授权设计落实到接口和执行顺序。沿用当前工作分支与模型环境；历史文件和运行产物保留。最终学习调度不在本次基线中假定完成。

## 统一的数据与执行接口

- `planning/context.py`：从现有 `paired_inputs.py` 提取 `input_size`、`fit_local`、`fit_remote`，原导入路径继续可用。新增 `build_plan_input(tokenizer, motion, evidence, feature_tokens, context_limit=4096, peer_reserve=1536) -> dict`，生成分开编码的本车/已查询邻车块、选择记录及 direct 提示。支持 P 观测、P 本地预测、F 和合法组合；不重新实现 compact 编码。
- `V2VGoTPlanner.plan_prepared(features, prepared) -> dict`：验证提示能由保存的证据重建，然后实际生成六点轨迹。现有 `plan` 增加明确的 `input_layout`，新框架固定 `source_blocks_v1`；旧 Q8/Q9 及历史入口保持可重放。在线运行、离线样本和评价使用同一个构造结果。
- `tools.vehicle.make_evidence(..., predict_p=True)`：保持现有默认 P 本地 MTR 重算，增加纯观测接收。纯观测不调用预测器、不伪造预测字段，来源区分 `:P`、`:P_local` 和 `:F`。本次基础训练明确使用已有 `local_mtr` 接收设置，纯观测为显式可执行选项，不宣称两种路径均已训练。
- `planning/episode.py`：`choose_action(state, policy)` 与 `run_episode(local_window, local_prediction, motion, service, predictor, policy, predict_p=True, max_calls=2)`。状态只有本车信息、实际已购证据、历史与预算；每步先选请求，再执行，再更新。固定 Ego/P/F/PF 和规则策略均走同一循环。终止、空结果、实际报文及失败全部保留。

初版规则的定义：车辆速度不超过 0.5 m/s 时 STOP；其他情况先向前方 ROI 请求 P（xmin=-5、ymin=-10、xmax=max(20,3×speed)、ymax=10，米）。若返回目标中有当前几何上无本车对应候选的目标，则对同一 ROI 请求 F，否则停止。空结果表示没有返回目标，不能解释为该区域安全。该规则是功能基线，不是学习策略或最优查询标注。

查询次数上限为 2。P 本地重算在一次任务内按已接收窗口复用，不能与远端 F 共用免费计算结果。每个固定对照重新建立查询服务；成本记录实际执行的行为。本轮规则不读取初始驾驶轨迹，因此不额外执行一次驾驶生成，也不使用未来 GT 作为查询路线。

## 实际运行、训练和评价

- `planning/run_framework.py`：读取已清理的配对数据因果索引；加载一次冻结 MTR、一次 tokenizer；按每帧每策略执行真实工具循环并构造最终驾驶输入。仅生成运行材料时也执行同一循环；生成模式加载原驾驶器并调用 `plan_prepared`。未来标签模块不进入在线进程。
- `scripts/prepare_framework_training.py`：独立离线读取已完成任务与原离线标签，使用现有 `supervised_examples` 导出训练行；验证输入不带答案。记录输入布局、P 接收设置、样本和任务产物位置。失败运行不伪造训练行，导出前报告完整覆盖。
- `planning/train_driver.py`：复用原 GoT 可训练 LoRA/projector 和 `encode_supervision`。提供完整多样本循环、验证损失、模型与优化器状态保存、明确继续训练入口。只对 assistant 目标和 EOS 计算损失；模型输入不包含未来标签。真实生成独立于 teacher-forced 验证损失。
- `evaluation/framework.py`：从完整任务记录与实际生成答案计算轨迹误差、失败分母、调用数、请求/响应字节、停止原因及逐录制组统计；同帧 Ego 对照只在双方有效时计算配对差，同时另报全部失败。保留简单运动外推参照，不能把它冒充原模型。

所有新目录采用独立版本，不覆盖 `paired_driving_data_v1`。源特征、预测权重和标签继续复用；现成文本只有在新公共构造器重建一致时才直接沿用。

## 执行顺序与验收

1. 记录当前测试基线；为来源分离、真实结果决定第二步、零调用隔离、P 可选重算、输入一致性加入回归检查，先观察缺失实现导致的失败。
2. 完成公共输入构造和任务循环，运行对应测试。采用真实 tokenizer 验证新入口重建现有 Ego/F 提示，同时覆盖 P/PF 容量。
3. 完成真实数据入口与离线导出，检查每个任务的调用、证据、停止与提示能一致追溯。先做少量真实完整任务调试，随后使用既有录制划分准备完整基础训练数据。
4. 完成训练、保存、继续训练和生成评价入口；实际运行原模型，不把单元测试当作模型已执行。训练覆盖 Ego/P/F/PF 与规则策略终态，使用相同驾驶权重和输入布局。
5. 完成统一评价、必要的独立审查与文档更新。训练未结束、生成未执行或仍有输出故障时必须如实保留状态，不宣称框架已具备驾驶收益。

基础适配使用一套配置：原 GoT 初始化，direct 六点任务，冻结 MTR；AdamW，LoRA/projector 学习率均为 2e-5、梯度裁剪 1、权重衰减 0、seed 20、有效批量 8、最多 3 轮完整曝光。每轮验证，按录制组与策略均衡的验证目标损失选择检查点，连续两轮无改善停止；不按 F 是否获益选模。训练轮数是本次基础适配设置，不声称原 GoT 复现或最终收敛已解决。实际训练开始前将完整配置和样本计数写入该运行目录。
