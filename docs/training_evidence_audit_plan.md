# 64 帧训练数据与模型输入核查

2026-09-11。用户同意先验证，并要求更容易理解当前工作。本轮沿用已接通的原 CMP MTR、原 GoT/V2V-LLM 驾驶入口；不新增查询机制，不训练驾驶模型。

要回答三个具体问题：原场景提供哪些自车/邻车信息；经过 P/F 和上下文预算后哪些信息真正进入模型；原驾驶模型能否在这些输入上生成可用的 Q8 父回答。结果用统计、原始失败和鸟瞰图解释，不以接口通过代替驾驶收益。

## 预先固定的执行规则

1. 仅从既有 research-train 的 3027 帧中选取 64 帧：8 个录制组各 8 帧。每组先取时间排序的 1/8、3/8、5/8、7/8 分位点，再取当前自车跟踪目标数量的 0、1/3、2/3、1 分位点；重复时取该排序中最近的未选帧。选择仅使用场景、当前帧编号和自车当前目标数量，不读取未来标签、邻车数量或模型结果。保存完整候选数量与选择原因，失败不换样。等组取样用于诊断，不代表全体训练帧的自然频率。
2. 冻结 `outputs/mtr_stability_v1/full_seed20/best_model.pth`。每帧通过现有 `planning.run_connection.prepare` 真正执行原 MTR、原浅层 projector 和 Ego/P/F/PF 四动作，保留原始请求、响应、预测数组、访问账本和完整证据。P 是邻车可用历史，F 是同源完整上下文先预测再返回。核对同信息 P 本地重算与 F 的所有预测数组。
3. 主格式 compact，另以 JSON 重算预算。两者均沿用当前 2 位小数、4096 上下文、540 自车点特征 token、256 生成预留和 128 Q8 父回答余量。只做诊断，不根据本轮样本调选择规则。分别统计证据记录数和唯一邻车轨迹编号；PF 的两条能力记录不能计为两辆车。
4. 两个发布驾驶初始化各执行 64×4 次 Q8 贪心生成，最大 128 token；共 512 次。输入包含自车当前/前一帧检测器浅层点特征，没有真实 RGB。保持同一份 compact 证据，保存回答原文、解析状态和真实生成开销。可解析 Q8 才构建 Q9 父提示并检查 256 token 生成预算；本轮不执行 Q9 生成或参数更新，非法回答不得补入 GT 父回答。
5. 离线分析独立读取未来自车 pose 标签，复算六个时刻的坐标、标签有效性、运动类别和监督序列长度；这些文件不得进入在线抽样、能力生成或 Q8 进程。近前方区域固定为 x∈[0,70]、y∈[-20,20] 米。几何未关联邻车轨迹只称候选，不推断为已证实遮挡目标。
6. 所有 64 帧保留在分母中。制作每录制组一帧加最多四帧诊断例，共 8–12 张鸟瞰图；明确图来自检测/因果跟踪重建，绿色未来轨迹仅供离线解释。查看完整信息、P/F/PF 实际保留内容及失败原文。

## 文件和验证

- `scripts/audit_training_evidence.py`：确定抽样、能力准备、容量统计、两初始化真实 Q8，使用已有生产接口。
- `scripts/report_training_evidence.py`：独立离线复算、图和可阅读报告。
- `tests/test_evidence_audit.py`：抽样不重复/等组/确定性、PF 物理目标计数及几何关联候选语义。
- 新运行目录 `outputs/training_evidence_audit_v1/`，保存开始时源码副本、固定 manifest、状态、逐帧结果和失败。旧结果原样保留。
- 完成后运行相关单测、仓库规定的完整与轻量检查，核对 64/512 分母、真实执行记录和原始结果，再更新状态与开发日志。

结论边界：本轮决定下一步输入表示和训练准备要先解决什么；不评判 ToolV2X 最终可行性，不证明规划质量、协作收益、闭环安全性或预训练数据无重叠。

## 执行中发现异常后的只读补查

固定样本 20/g2762 的两源跟踪为空，但原始检测双方均有 11 个过阈值目标。其前一间隔的 pose 平移约 67 米。为查清范围，追加研究训练片段内全部相邻 pose 的只读扫描，并标记固定 64 帧历史/未来范围是否跨过跳变；不替换样本、不更改在线输入或模型。诊断阈值预先记为单个标称 0.1 秒间隔平移 >20 米或航向变化 >20 度，仅用于定位人工复核点，不据此自动宣布其余数据干净或过滤训练集。原始保存帧号尚不等于已核实的传感器时间戳。

离线图审也发现：近乎静止时对厘米级路径位移求方向会产生很大的角度变化。展示改用 pose 航向，并要求累计路径至少 1 米、每个 0.5 秒段至少 0.1 米；不满足时路径切线变化标为不可靠，保留原始数值作诊断。此条件只影响解释与选图，不改变 64 帧分母或监督标签。
