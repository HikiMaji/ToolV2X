# ToolV2X 导航接入研究：输入选择、数据来源与最小改动

日期：2026-09-15。状态：研究建议，尚未实施导航模型、训练或闭环。用户要求先研究怎样加入导航，并明确暂不排查此前小样本训练退化。本报告不把旧数据、参考代码或接口设计当作已完成的导航训练。

## 1. 建议与决定依据

建议正式导航版本先使用**一个没有到达时间约束的局部导航目标点**。目标点来自决策前已给定的路线，转换到本车当前坐标系；以小型 MLP 编码为一个 token，加入现有共享数值驾驶器的注意力输入。首版不同时加入高层指令、完整路线编码器或地图网络。目标点并不能完整表达任意复杂路线；若实际场景存在目标点相近但道路分支不同的歧义，再考虑短路线片段。

| 候选表示 | 优点 | 首版取舍 |
|---|---|---|
| 左/右/直等高层指令 | 维度低，对精细导航依赖小 | 对转弯距离、道路几何和不同出口区分较粗，不选为唯一正式输入 |
| 一个局部路线目标点 | 包含方向与距离，已有原生采集/在线使用链路，能复用普通数值编码 | 推荐；仍需检查复杂分支歧义和直接追点偏置 |
| 短路线片段 | 能表达连续道路走向和部分分支区别 | 数据/编码接口更复杂；有明确场景需求时再升级 |

导航是驾驶任务条件，P/F 是获取环境证据的远端能力。导航帮助初始方案及修订方案符合行驶目的；P/F 的 current/change 仍然由实际生成的新旧方案确定。导航不直接替代方案、ROI 评分或最终驾驶输出，不构成新的工具或论文创新。

当前存在一个不能靠添加字段解决的数据缺口：现有 V2V4Real/GoT 处理结果没有经过核实的预设路线或导航目标。不能同时声称“只用现有处理数据”“不使用事后轨迹构造输入”“已经有真实导航监督”。推荐保留真实数据的无导航开环设置，并用有原生路线记录的数据建立导航版训练与后续闭环。它们可以复用模型设计和 P/F 方法，但属于不同数据条件，不能混成一张未经说明的同协议结果表。

## 2. 实际核对的参考链路

| 参考 | 输入如何生成 | 模型如何使用 | 本项目可借鉴的部分 |
|---|---|---|---|
| VAD 本地参考源码 | converter 根据真实未来轨迹最后一点的横向偏移生成三类 command | head 输出三种规划模式，command 参与模式监督/选择；不是简单地把一个导航 token 喂给所有路径 | 粗粒度意图条件与有效监督；不能把离线推导的 command 说成原始在线导航 |
| V2Xverse 数据采集 | `_command_planner` 从 `_global_plan` 取节点；记录 `x_command/y_command` | dataset 用当前 measurements 和当前姿态转换目标点，未来 measurements 另用于轨迹监督；planner 用 `MLP(2,128)` 编码目标点并与场景特征拼接 | 原生路线来源、训练/监督分开、小型数值编码 |
| V2Xverse 闭环 agent | 路线规划器根据当前 GPS 返回下一节点 | 转换为 local target point，供规划推理 | 可作为闭环适配端的参考；不等于整个协作平台已经接入 |
| TransFuser 2022 | loader 从当前帧 measurements 读 `x_command/y_command`；在线 agent 从 `_global_plan` 更新目标 | 目标点可拼入 GRU 输入，并可编码为图像通道 | 证明目标点是常用可执行接口；不搬入它的 GRU、图像通道或骨干 |
| Hidden Biases，ICCV 2023 | 比较目标点和离散导航指令条件 | 指出目标点可形成恢复偏置，影响路线完成和转向；对远目标的直接追随也可能出错 | 共同导航条件与简单导航基线必不可少；新增注意力 token 不等于自动消除了偏置 |

可追溯的官方来源：[VAD converter](https://github.com/hustvl/VAD/blob/main/tools/data_converter/vad_nuscenes_converter.py)、[V2Xverse 采集](https://github.com/CollaborativePerception/V2Xverse/blob/main/simulation/leaderboard/team_code/base_agent.py)、[V2Xverse loader](https://github.com/CollaborativePerception/V2Xverse/blob/main/codriving/data_utils/datasets/planning_with_gt_dataset.py)、[V2Xverse planner](https://github.com/CollaborativePerception/V2Xverse/blob/main/codriving/models/planning_end2end.py)、[V2Xverse agent](https://github.com/CollaborativePerception/V2Xverse/blob/main/simulation/leaderboard/team_code/pnp_agent_e2e.py)、[TransFuser loader](https://github.com/autonomousvision/transfuser/blob/2022/team_code_transfuser/data.py)、[TransFuser agent](https://github.com/autonomousvision/transfuser/blob/2022/team_code_transfuser/submission_agent.py)、[Hidden Biases 论文](https://arxiv.org/abs/2306.07957v2)。

参考代码也需要审查，不能照抄默认参数：本次保存的 V2Xverse 采集端 command planner 参数为 7.5/25.0，而闭环 agent 的 route planner 参数为 2.0/10.0。两者都来自路线，不证明每帧取到相同节点。其 loader 还对目标点裁剪、将 NaN 置零。ToolV2X 应统一离线/在线取点规格，显式记录裁剪或缺失，避免把无效导航悄悄变成原点。

本次参考来自读取时的 main/2022 分支快照，不保证远端以后不变。具体文件、来源 URL、读取时间和字节数见本地研究目录的 `sources.json`；没有执行这些参考仓库的训练或仿真代码。

## 3. 现有数据究竟具备什么

完整扫描当前准备清单的 3,095 行：2,987 train、108 development validation。字段只有样本/场景/时刻、角色、当前运动与特征/运动读取路径，没有 navigation/route/command/goal/target_point 等导航字段。两个本地仓库的常见地图格式和导航文件名检查也未找到候选。该检查不等于穷尽所有原始压缩包中可能存在的元数据。

更重要的是，V2V4Real 官网虽介绍 HD 地图，下载区仍标注 `HDMap annotation: [next version]`。本次通过直接 HTTP 获取并保存了页面，不能继续假定“补一次地图下载就能解决”。即便取得路网，仍需知道当次驾驶事先选择的路线。来源：[V2V4Real 官网](https://mobility-lab.seas.ucla.edu/v2v4real/)。

导航来源分为以下几类，必须分开记载：

| 来源 | 首版主设置是否接受 | 原因 |
|---|---|---|
| 仿真开始前的路线 + 当前定位，或真实系统决策时已有的导航日志 | 接受 | 可在时刻 t 获得，有明确任务语义 |
| 人工提前指定目的地/道路序列 + 静态地图 + 当前定位 | 有条件接受 | 可以构成新的路线任务；但不能假定已有专家轨迹就是该任务的正确监督，必须另行核对 |
| 根据记录未来轨迹推导左/右/直 | 仅可作为披露清楚的离线意图条件实验 | 不能混入“导航原本在线可用”的主设置；本次不生成此类标签 |
| 直接取真实 t+3s 位置，或把真实未来轨迹去时间、稀疏化后作为目标/路线 | 不接受 | 依赖待预测答案；去时间或增加距离不足以证明独立性 |
| 根据当前速度外推一个目标点 | 不作为导航 | 没有新增目的地信息，仍是运动基准 |

本轮已从 [V2Xverse 官方数据](https://huggingface.co/datasets/gjliu/V2Xverse) 的展开目录下载一个 Town03 路段、`ego_vehicle_0` 的 `0000/0001/0010.json` 三条 measurements，总计 **28,430 字节**。三条均有有限的 `gps_x/gps_y/theta/x_command/y_command`，且目标点等于记录中的 `far_node_x/far_node_y`，与所读采集代码的写入链路相符。未下载数百 MB 的路线压缩包。

按参考 loader 的公式重算，0000/0001 的目标约为 `[0.000068,-31.730002]` 米，0010 为 `[0.173549,-30.214188]` 米。这是 **V2Xverse loader 的坐标约定**，尚未验收它与 ToolV2X `ego_at_t` 的轴向、传感器原点和位姿是否一致，不能直接拷贝两个数作为本项目输入。三条也不构成路口/转弯覆盖。

记录同时含专家动作、`target_speed`、`future_waypoints` 等其他字段。首版导航解析只读取明确允许的路线目标及当前定位字段；其余不能因为在同一个 JSON 中就自动进入驾驶器。参考 loader 中名为 `command_waypoints` 的张量实际上来自后续帧自车位置，属于轨迹监督，不是导航输入。

这次完成的是来源代码与小样本字段核对。样本对应的原始路线配置、采集版本、正式划分和与本项目观测/标签的绑定尚未完成；样本仅用于研究，不进入训练或正式评价。主数据、感知输入、跟踪/MTR 接入仍需适配，不能因为有导航 JSON 就说现有 ToolV2X 已能在该数据集训练或闭环。

## 4. 最小输入与执行语义

下面均为建议接口，不是已存在 API。

`navigation` 记录建议包含：版本、scene/g、自车标识、坐标系、`goal_xy_m`、可用状态、路线来源及提取规格版本。`goal_xy_m` 是两个有限数值，位于与 P/F、ego history 和输出一致的 `ego_at_t` 坐标系；不附带真实到达时刻、目标车速或专家动作。

路线标识和来源只用于复现/审计，不作为网络特征，也不使用绝对路径充当语义身份。完整预设路线保存在本车导航侧，目标点是给驾驶器的局部视图。若上游有近/远节点和 command，先保留其原始来源供审计，首版网络只使用一个已选定的目标点。

离线/在线使用同一版本化取点规格：相同路线上根据当前及过去进度推进，不使用事后真实车辆位置定位进度；重复点和等距候选按路线顺序处理；路口分支由已给定路线决定。采样/推进距离、坐标归一化、目标范围等属于实验规格，不能散落为协议常量。若复用已有采集目标点，记录其实际提取规格，不假称与新取点器完全相同。

本轮选择语义和接口形态，不冻结缺乏实测依据的取点距离。第一次真实小样本导航接入时，依据所选导航源形成一份完整参数配置，再运行契约验收；不能用“待定默认值”生成正式训练记录。

单次时刻 t 的流程：

```text
预设路线 + 当前定位 → navigation_t
本车感知/运动 + navigation_t → τ0
真实 P/F 请求(τ0) → 返回证据 + 同一 navigation_t → τ1
第二次请求(τ1，必要时 τ0) → 返回证据 + 同一 navigation_t → τ2 / STOP
```

最多两次远端调用、三次驾驶尝试照旧。单次调用链冻结 navigation_t；执行车辆控制并进入下一时刻后，导航系统才根据新定位更新局部目标。不能在某个协作臂偷偷换路线，也不能由 peer 返回内容改写本车任务。

导航缺失需区分两种模式：旧无导航版本按原输入继续可读；新的导航必需版本遇到缺失就明确报告该样本不具备导航输入，不将其填成 `[0,0]`。若将来要用缺失掩码做混合训练，必须另做明确的训练设计；本次不增加未使用的混合模式。

## 5. 对当前代码的最小影响

| 部位 | 建议修改 | 必须保持的边界 |
|---|---|---|
| 新的导航解析/转换小模块 + `run_framework.py`/相应数据接入端 | 将已有路线目标和当前定位转成统一 navigation；将语义记录绑定到 task row/episode | 不读取独立未来标签；数据集适配与导航接口不能混成一个假通用加载器 |
| `structured_inputs.py`：`build_structured_plan_input`、`validate_structured_prepared` | 增加导航版 prepared layout 与严格 navigation 校验 | 当前严格字段集合会拒绝新字段，必须显式版本化；不改写旧归档 |
| `structured_driver.py`：`prepare_input`、`collate_structured_inputs`、`StructuredPlannerNetwork.forward` | 传入二维目标、归一化后小型 MLP 生成一个 d 维 token，加入已有 memory；更新 token 成本 | 普通工程层，不包装网络创新；保持 P/F 数值编码和原输出六点语义；不额外监督六点终点等于导航目标 |
| `method_episode.py`、`driver_contract.py` | 三阶段绑定相同导航；重建 prepared 时纳入导航一致性 | exact-repeat 必须完全相同；same-evidence refinement 只按既有约定换 prior，不能换导航 |
| `train_structured_driver.py` | 导出行及模型/数据绑定保留导航；每个前缀 forward 读取同一个导航；新 driver spec/checkpoint 显式区分 | 当前模型生成 detached prior 的方式保留；不从 supervision 回填导航；更换输入/架构不叫精确 resume |
| `evaluation/structured.py`、共同评价导出 | 记录导航可用性、来源版本、入模位置及失败分母；配对比较检查导航相同 | 导航是本车任务输入，不计入远端 acquired/derived 字段和收到的字节 |
| P/F provider、`tools/task_spec.py` | 首版无须增加导航字段 | 服务只根据 τ_new/τ_old 排序；P 不运行 MTR，F 完整上下文后裁剪；不改 v1 wire/golden |
| `query_value.py` 与强单轮委托 | 首版保持现有特征与 wire 接口，导航先通过实际生成的 τ 影响请求；分支根记录需绑定共同导航条件 | 现有 query state 严格白名单不能直接塞 `target`；不单独给 feedback 额外导航特征造成不公平 |

最后一项是明确的首版简化：价值模型没有直接读取导航，可能损失超出短时 τ 表达的意图信息。如果后续证据表明必须直接使用，应同时版本化 feedback 特征、one-shot 可见摘要与通信费用，重新训练相应策略。当前不是新增这一套机制的时机。

普通 token 注入只证明接口能接入，不能保证初始模型按导航转弯。旧数值 v2 未训练过导航；旧权重可以作为保留基线，若要迁移公共权重需显式 warm-start 设计，不能简单宽松加载后宣称原恢复契约成立。训练所需的数据仍必须有真实导航。

## 6. 必要验证与论文对照

实施时先做以下有针对性的检查，不在本研究阶段运行模型：

1. **来源隔离：** 修改/移除未来轨迹标签，不改变从预设路线和当前定位得到的导航。标签可以用于离线评价，不能影响导航转换。
2. **坐标与时间：** 平移/旋转等变、左/右方向、车辆原点与传感器原点差异；同一条记录的离线和在线适配输出一致。只写 `ego_at_t` 标签不算通过。
3. **路线进度：** 等距、重复节点、路口、路线终点和缺失输入有确定行为；不得使用未来自车轨迹确定将来经过哪条分支。
4. **真实入模：** 目标点经过 collator 到达指定 token；有效输入梯度和参数路径可检查。未经训练时输出变化不是导航正确性证据。
5. **三阶段与控制：** Ego/P/F/PF、feedback、frozen-feedback、strong one-shot、same-evidence extra-generation 共用导航；更改导航后禁止复用旧分支监督冒充同一个状态。
6. **恢复和兼容：** 新导航版训练/重载输入一致；篡改导航内容或提取规格使恢复绑定失败；旧 v1 wire/旧数值数据正常回归。

后续模型效果检查应包括：共同导航条件下的 Ego/P/F/PF；不读环境的简单导航跟随/运动参考；feedback 与 strong one-shot、固定证据额外生成。导航消融单独衡量基础改动，不能把加入目标点的收益计为远端调用创新。对修改导航而没有对应专家行为标签的样本，只检查行为响应/路线条件，不能沿用原标签报“更准确”。

闭环需要在共同路线与背景配置下报告碰撞、路线完成、停车/超时、通行时间，以及通信与全部计算成本。当前无地图/道路边界分支、感知输入格式、控制器与仿真适配仍是另外的工作；导航 token 的加入不会自动解决这些问题。本轮不扩展成新的地图、世界模型或 RL 项目。

## 7. 按依赖顺序的下一批建议

**N0：导航数据小样本接入。** 本轮已取得三条真实 measurements 并核对来源代码；下一步补对应路线配置/采集版本、坐标与单位的确定映射，检查能够与自车当前观测及独立未来监督按帧绑定。产物是小样本导航清单和转换验收，不需要新权重或整套数据下载。研究样本不自动进入训练或正式测试。

**N1：导航输入契约与共同驾驶器接入。** 按第 5 节完成版本化 prepared/driver、一个导航 token、三阶段冻结和兼容测试；首批到此停止。这一步不代表导航能力已经学会。

**N2：有导航数据上的共同适配。** 先完成该数据源的感知/跟踪/F 输入及划分适配，再用真实有导航样本训练；配对评价后决定规模。现有 V2V4Real 可以继续作为无导航真实数据证据，但不冒称已经成为导航训练集。

**N3：闭环补充。** 采用同一导航源/取点语义，接控制执行并检验连续反馈。无需重新定义 P/F 或加入 RSU；是否采用 V2Xverse 全框架需另据适配成本决定，本轮只选它的导航链路作参考。

本轮建议采用 N0→N1，而不是立即扩大无导航数据采集后再修改输入。压缩读写准备可以独立推进；小样本训练退化诊断仍后置。尚未获得可靠导航来源时，不伪造导航记录，也不把几何转换检查当成训练效果。

## 8. 本轮实际产物与执行边界

本机研究材料位于 `outputs/navigation_research_2026_09_15_v1/`：参考源文件、论文 PDF/正文、来源索引、3,095 行导航字段检查、官方数据目录元信息、三条 measurements 与本仓库源文件快照。公开精简证据见 [证据说明](evidence/navigation_research_2026_09_15/README.md)。

本轮只进行读取、资料下载、正文提取和研究记录；没有修改生产源码、训练配置或旧结果，没有 GoT/MTR/driver 推理、梯度更新、全量数据下载、仿真、GitHub 提交/推送。小于 100 MB 的资料按已有授权下载；不能从目录元信息推断整个数据集已经可用。实际小样本下载结果与完整来源计数以精简证据为准。
