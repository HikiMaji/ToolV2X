# ToolV2X 主线创新筛选：驾驶方案修订驱动的远端再请求

日期：2026-09-12。性质：候选机制研究与源码、文献核查；具体算法尚未确定，尚未生成本候选的训练标签或运行方法实验。

已确认：本车按当前驾驶需要调用邻车能力，返回后调整下一步；两车 P/F、原 GoT/MTR、时间 t 因果输入、首版最多两次调用；RSU/I 后置。用户本轮允许寻找合理的新机制。本文采用阶段 B 的方法深化思路，记录候选与取舍，不冒充已经确认的正式 Method。

## 1. 本轮结论与取舍

**优先深化“驾驶方案修订驱动的远端再请求”，把“区分观测增量与上下文计算增量的价值学习”作为配套机制。** 具体研究：第一次 P/F 返回与本车完整本地证据融合，令同一 GoT 产生修订方案；旧方案与新方案的交互关系变化，能否帮助本车提出比普通二次查询更有用的远端任务？初始 STOP/P/F 保留。

本轮最重要的否决发现是 **MATE 已让 ego 发送候选轨迹，由 peer 利用私有代价图计算并返回评价**。因此，初步考虑的“两条初始探针＋远端判断”不够构成清楚的核心。最终候选明确要求真实首次返回、实际 GoT 方案更新，以及针对更新后任务的再请求；不是只把初始轨迹换成一组查询参数。[MATE §III-B](https://arxiv.org/html/2303.06080#S3.SS2)

这是一项核心候选及其学习支撑，不是已经发现两个经过验证的新算法。协议参数、计划对比、任务损失、两步价值和小网络各自都有直接先例；可能的论文增量在于它们如何共同处理**本车有驾驶需求、邻车有私有场景，P 与 F 具有不同算子上下文**这一具体分工，以及是否优于公平的简单方法。

| 候选 | 具体新增 | 判断 |
| --- | --- | --- |
| A：方案修订驱动的 P/F 再请求 | 用首次返回后实际生成的新方案与旧方案构成请求，邻车检索相关 P/F 证据；本车决定是否值得执行第二次调用 | 优先研究；关键是旧→新关系能否超过只用新方案的查询，且胜过公平的一轮委托 |
| B：按算子上下文区分调用价值 | 固定目标和原始观测，分别量出完整邻车上下文预测与原始历史补充对驾驶的作用，用于训练下一步能力价值 | 作为 A 的学习支撑；独立评议更偏好它，因现有代码更容易形成严格对照 |
| C：条件化远端能力委托 | 请求附受限 P→条件判断→F 程序，在邻车完成中间判断，返回执行结果 | 部署变体与强单轮对照；条件编排本身已有直接先例，不单列创新 |

此前 [预测补证候选](innovation_design_2026_09_12.md) 保留为 F 后继续查询的一种局部分支。本文保留初始 STOP/P/F、直接调用和不同顺序，不把先 F 设为必经步骤。

## 3. 主候选 A：第一次返回后，驾驶问题怎样改变

### 3.1 大白话示例

例如，本车原方案保持行驶，第一次 P 返回补充了此前缺少的目标历史。本车将它与自己的完整本地证据一起交给 GoT，得到一个减速后的方案。此时下一问可以表达为：“按这个修订方案行驶，与原方案相比，哪些目标的交互时段发生变化，值得进一步预测或补充观测？”

如果再选 P，邻车从当前状态和一秒历史中检索相关目标，返回原始历史；如果再选 F，邻车利用其完整上下文运行原 MTR，返回相关目标的多模态预测及对应时段。也可能第一次返回后直接停止。**这只是机制示例，尚不是本项目已经出现的成功案例；修订后的方案也不预设比原方案正确。**

初始 F 允许按任务区域搜索未知目标，不要求先 P 获得 ID；初始 P 同样合法。本车没有提前得到邻车的目标清单。后续目标句柄只能来自真正收到的报文。

### 3.2 最小完整流程

**第一步：形成本车初始方案。** 输入本车截至 t 的状态、原点云特征和已有本地证据，由同一 GoT 产生初始轨迹。输出该轨迹、任务范围和当前运动信息。它是模型真实生成的方案，不代表已经验证道路可行或安全；本候选不需要假设 GoT 具有多候选评分器。无效生成按统一规则处理并报告，不能只留下有漂亮修订的帧。

**第二步：决定是否发问及调用哪项能力。** 输入本车任务表示、已购证据和剩余预算。策略选择 STOP、P 或 F，以及一个有限的任务范围/时间段。输出结构化请求。首版可用同一路径的早、中、晚三个时段作为有限参数集；参数数量是工程取舍，不是创新。

**第三步：邻车执行具体任务。** 输入请求和邻车自己的因果窗口。P 执行器只从当前及历史状态生成检索特征并选择原始观测；F 执行器保留完整邻车上下文，对请求确定的预测中心执行原 MTR，再整理作用时段与模式。未知目标可以由 peer 用因果状态和请求区域在本地寻址；任何借助完整 F 才完成的筛选，都应计入完整 F 的实际计算。输出是来源、目标、时间和真实 P/F 数据，可附可重算的相对几何量。

**第四步：用实际修订组织下一问。** 本车将第一次报文与完整本地输入合并，用同一 GoT 生成修订轨迹。以“旧方案、新方案、已购证据、剩余预算”预测第二次 P/F 请求的价值；请求中的旧→新交互关系用来定位值得重新检查的目标或时段。该更新同时保留新方案的绝对任务需求，不能只看变化区域。方案不变不自动 STOP，变化很大也不自动多问；是否继续由预期任务收益与成本决定。只用运动学探针或小网更新区域的版本作为基线，不能冒称实际 GoT 方案修订。

**第五步：输出最终轨迹。** 如执行第二次调用，同一驾驶器使用新增证据产生最终三秒六点轨迹；如 STOP，复用与当前证据对应的方案。因此完整两调用路径通常需要三次 GoT 生成：初始、第一次返回后、第二次返回后。全部计入成本，并让普通查询与一次委托对照拥有相同的可用计算预算。

### 3.3 必须落实的学习结构

最小候选包含两个相互配合的部件：

- **本车请求价值模型**：读取本车任务表示、实际旧/新方案及其关系、已获证据、合法请求参数和成本，预测每个候选 P/F 请求的终态任务收益，并与 STOP 比较。首步尚无修订，用显式缺省状态。
- **邻车任务执行中的目标排序模型**：P 分支读取真实历史与任务参数；F 分支读取完整上下文 MTR 结果与任务参数。在声明的报文预算内选择目标块，返回原始数据及筛选依据。P 不得先偷跑 F 来给自己的目标排序。

旧/新方案与已知对象的距离变化、相交时段变化、历史变化等可以作为关系特征；peer 用自己的合法 P/F 数据计算对应关系。**几何差异与方案位移不能直接当作任务收益真值。** 离线在训练录制组上固定真实第一次返回、同一驾驶器、本车输入和接收格式，交付不同合法第二次目标块并生成最终轨迹，以轨迹误差变化和成本形成排序/价值监督。单目标或贪心增补只是可实现的近似，不能据此证明多目标交互已完整建模。

最小结构保留新方案的绝对关系特征，同时单独编码旧→新的变化关系，再对可选 P/F 请求和目标块评分。这个结构的待验证假设是“变化关系对再次获取证据有用”；拼接、相减、排序损失本身不是新算法。必须用相同输入、监督和参数量的普通模型检验这个结构是否有增量。

旧方案是已有输入经模型得到的结果，变化关系也没有创造新的物理观测。这里研究的是一种用于请求生成与价值学习的结构，而不是声称它增加了信息论上的独立信息。若绝对任务关系已经足够，删除这个结构是合理结果。

两个模型的普通网络结构、监督回归或排序损失均属实现工具。真正需要验证的是：本车融合两端信息后出现的实际方案修订，能否指导比新方案单走廊、固定两轮或一次 peer 计算更有用的 P/F 再请求。固定解码设置并共享随机性，避免把生成噪声当成证据引起的方案变化；同证据重复生成是必要的归因对照。

初始两步价值使用合法的续调用策略：先拟合第二步，再用按录制组交叉拟合、冻结的续策略产生首步训练结果。逐帧用未来 GT 挑出的最优第二动作可以作为离线上界；它不等于部署策略能取得的收益。

## 4. 配套候选 B：分清楚下一次调用的收益来自哪里

### 4.1 来自真实代码的结构

当前完整 P 包含邻车历史，本车可用同一个 MTR 重算；局部 P 只包含已返回的窗口。远端 F 则先在邻车完整窗口预测，再裁剪输出目标。**预测的目标集合与计算所用上下文集合是两件事。** [服务与本地重算](../src/tools/vehicle.py)、[MTR 中心与上下文构造](../src/prediction/cmp_adapter.py:26)

所以，对于同一个已经找到的目标，可以存在两类不同需求：

1. 当前历史已经收到，但用这些历史重算的预测缺少邻车其他上下文；值得考虑直接委托邻车计算 F。
2. 远端 F 已经收到，但驾驶器仍可能需要预测报文没有保留的原始历史；值得考虑 P。

这是条件关系，不保证完整上下文更准确，也不要求强行保留两步调用。

### 4.2 可执行的配对监督

固定同一个目标块、背景对象、本车输入、原始 P 和接收容量，构造三个离线终态：

| 终态 | 输入 |
| --- | --- |
| E1 | 局部 P 的原始历史＋用已收上下文本地算出的该目标预测 |
| E2 | 同一份局部 P 原始历史＋邻车完整上下文产生的该目标预测 |
| E3 | 与 E2 完全相同的远端预测，去掉该份原始 P 历史 |

E1 与 E2 的实际驾驶生成误差差异，用于监督“委托完整上下文计算”的任务增量；E3 与 E2 的差异，用于监督“补原始历史”的任务增量。标签允许为负；格式失败另记并采用预先统一的处理规则。这不是物理世界的因果干预，也不表示识别了真实预测错误原因。

返回后价值模型共享任务/证据编码，但分别学习这两类增量。在完整 P、同一 MTR、相同输入与接收表示的等价条件下，E1/E2 应收敛为同一信息条件；如果差异来自源标签、重复文字或截断，不能算 F 的新能力收益。

这些标签只监督对应的受控增量。首次 STOP/P/F、P 或 F 带来新目标、不同任务范围以及多目标组合，仍需其合法终态的实际收益标签，不能全部硬归入上述两项。

**B 的核心风险：它可能只是普通多任务模型的一种标签组织。** 必须让普通模型获得完全相同的 E1/E2/E3 监督、任务特征和更新预算；如果结果相当，保留它解释 P/F 关系，取消算法创新表述。[独立驾驶评议](mainline_driver_mechanisms_2026_09_12.md)

## 5. 合理新增 C：条件调用可以委托在邻车完成

本车可在一次网络请求中附受限的条件程序，例如先执行 P，再根据返回目标和本车已发送的任务条件决定是否对部分目标执行 F。中间结果不必全部往返。这保留任务驱动能力调用，但扩展了后续决策的执行位置，应显式标明。

**一次网络请求不等于一次能力调用：P 与 F 各计一次，最多两次能力调用的限制继续成立。** 本车摘要、条件参数、返回证据、所有计算分别计费。

本轮将它作为强对照：如果这种简单一轮委托已达到交互两轮相同的质量—成本效果，就不主张回到本车再发问的必要性。只有额外通信/上下文的真实取舍支持时，才讨论执行位置。条件程序和函数下推已有先例，当前不将 C 列为方法贡献。[LLMCompiler §3.4](https://arxiv.org/html/2312.04511#S3.SS4)

## 6. 从现有框架到本候选，实际缺什么

| 模块 | 当前事实 | 候选需要增加什么 |
| --- | --- | --- |
| 请求 | `VehicleTools.query(tool, roi)`，按当前框中心裁剪 | 任务参数、可选已知目标句柄、时间范围/响应预算及对应校验 |
| 远端 F | 先预测全部目标，后裁剪 | 任务执行/目标排序；若进一步节省预测计算，需显式选择预测中心并保留完整上下文 |
| 驾驶与查询交替 | 查询结束后才执行 GoT | 若采用真实临时方案，增加规划状态与中间 GoT 调用，计其真实成本 |
| 证据接收 | P_local 与 F 作为源块追加 | 统一同目标历史、预测的保留/替换语义，给全部对照相同表示和容量 |
| 学习 | 五条件共享驾驶适配，固定/规则查询 | 请求价值与邻车目标排序标签、B 的受控配对监督及对应小模型 |

依据：[查询](../src/tools/vehicle.py:58)、[返回后规则](../src/planning/episode.py:11)、[执行器](../src/planning/episode.py:36)、[原 MTR 输入](../src/prediction/cmp_adapter.py:26)、[接收表示](../src/planning/context.py)、[原驾驶生成](../src/planning/v2vgot.py)。

现有 GoT/MTR、因果窗口、轨迹标签与统一执行评价可以复用。新表示需要公平适配时再增加对应训练，不能将旧五条件 SFT 当成新查询器已经训练完成。现有 MTR 没有 ego 行动条件；本候选的任务参数只改变检索/请求，不能宣称模拟邻车对本车方案的反应。

原 MTR 的中心对象可单独选择，但每个中心仍输出 50 个未来时刻；请求某个时间段只改变返回整理，不能据此宣称减少时间维解码计算。

当前 `coverage=not_established`，空返回只能表示缓存中没有符合条件的已观测目标。任务执行器不能把它升级成“区域安全”。F 的六个保留模式分数也不是校准的碰撞概率；跨目标同序号不是共同交通场景。

| 要回答的问题 | 必要的公平对照 | 不成立时的取舍 |
| --- | --- | --- |
| 旧→新方案关系确实改善再请求吗 | 旧方案不更新、新方案单走廊、旧/新并集或差异区域；同输入同监督的普通关系排序器 | 若只用新方案就打平，取消“修订关系”核心；若完全不更新也打平，任务更新亦无证据 |
| P/F 结构带来的监督有用吗 | 同输入、参数量和 E1/E2/E3 监督的普通 AFA/多任务模型；完整 P＋本地 MTR、完整 F | B 降为诊断与协议说明 |
| 返回后的再次决策值得吗 | 同一初始任务信息与总预算的 learned one-shot bundle、条件委托 C、固定组合，以及 MATE 风格直接方案评分 | 序贯降为可选执行分支；仅一轮请求仍需相对 MATE/任务相关通信另证增量 |
| 改进来自获取机制吗 | 共用充分适配的原 GoT、相同本车信息/接收容量、普通数值 adapter；同临时规划计算预算 | 分开报告底座、表示与查询收益，不能把 adapter 修复计作工具策略贡献 |

两轮不需要有更高的全知 oracle 上界；相同可达终态可以有相同上界。应比较部署时实际可见信息下取得的质量和成本。调用次数、实际双向字节、MTR 与 GoT 计算、接收 token 分开记录；未实测无线链路时不宣称实车通信时延收益。

一轮方案必须能获得相同初始请求、在 peer 内做条件计算，并允许在预算内上送更多 ego 摘要；这些额外字节如实计入，不能禁止廉价摘要制造优势。它不能免费获得仅在 ego 融合第一次返回后才产生的新方案。比较 MATE 风格评分时，若原 GoT没有候选排序功能，应明确采用共同新增的候选生成/接收器进行接口对照；这不是完整 MATE 复现，也不能把预测分数误用成其熵图。

缓存的相同预测应给出相同任务内容，这是正确性而不是创新失败。缓存对照需报告预计算和缓存可用条件；若新实现只减少输出中心计算，其增量属于实际计算成本，不应声称多获得了信息。提供方原本已有全部预测缓存时，不能虚构重复计算收费来制造委托收益。

最终质量以实际生成 ADE/FDE、格式失败、按独立录制组的配对结果与适用/失效场景为准。改变请求而保持记录世界不变，只能检查接口是否按问题工作，不能声称构造了另一种真实驾驶未来或验证安全。

## 8. 下一步的单一推进方向

把 A 写成一份有限的请求—执行—返回规格，同时把 B 的三个受控终态接到同一规格中；最小版本只保留“首次返回引起方案修订后的再请求”这一问题族、P/F 两个真实执行器和一个共享驾驶底座。C 作为该执行器的单轮对照保留，不另起系统项目。

最先要形成的完整证据链是：**同一个因果驾驶输入 → 明确任务请求 → 真实远端执行 → 返回后合法决策 → 最终原 GoT 轨迹与完整成本。** 用它检验本候选与匹配 ROI、普通学习器和一轮 bundle 的差异。若只能证明报文变短或输出可解析，仍未回答核心研究问题。

论文现阶段可用“驾驶方案修订驱动的远端能力请求”组织 Method 候选。A 能否成为主贡献、B 能否成为第二机制，由上述匹配对照决定。最致命的两条风险是：旧方案信息可能对新方案查询没有额外价值；修订可能是 GoT 噪声或错误反应。此次交付完成的是候选筛选和可实现性定位，没有新模型执行、下载或对现有训练的修改。
