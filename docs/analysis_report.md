# ToolV2X：首轮正文分析与起步判断

日期：2026-09-07。输入方案：`../start.md`。阶段：A，分析稿，尚不是用户确认的 Part 1。

## 结论

**方向值得做前提探查；原方案不足以直接进入完整方法实现。建议保留 PROBE-GO，不升级 METHOD-GO。**

当前最可能成立的问题是：在请求前看不到远端结果的条件下，车辆能否依据当前规划和已返回证据，逐步选择远端感知或预测服务，使规划质量与真实获取成本之间的权衡优于一次性选择和简单规则。

这是待验证的问题，不是已经确立的新颖性。DriveAgent-R1 已覆盖主动工具调用、证据反馈、多轮获取、模式选择和收益减成本；协同通信文献已经覆盖规划相关区域请求；主动信息获取文献已经覆盖条件化的下一次查询。ToolV2X 必须证明这些机制在远端独有证据与异质能力条件下带来的具体新增价值。

不把显存、设备数量、数据下载或规模作为限制。因果输入、对照公平和任务可验证性属于科学条件，仍需满足。本轮没有训练、模型推理、闭环运行或统计实验。

## 一、四篇关键论文如何改变对原方案的判断

### DriveAgent-R1：直接机制近邻

其初始输入为前视图、速度和导航；按历史上下文生成思考与工具请求，工具结果编码后追加进历史，再生成后续请求或最终动作。工具包括多视角/历史帧获取、ROI 放大、深度估计、3D 检测。正文 2.1 与附录 A.2 已明确这些机制。[论文](https://arxiv.org/abs/2507.20879)

附录 A.5 的工具奖励为：

\[
R_{tool,i}=(R_{acc,i}-\overline{R}^{text}_{acc})-N_i C_{tool},\qquad C_{tool}=0.125.
\]

这是总奖励的一部分：还包含准确性与格式奖励；工具子奖励被裁剪，没有文本模式样本的组不施加该项。它不是 ToolV2X 所需的逐服务、逐状态反事实价值估计，但已覆盖“比较不用工具的效果，再惩罚调用成本”的核心思想。

**修正初查边界：不能说它只做高层动作而完全没有轨迹评价。** 最新版正文 3.3 用冻结模型加 MLP，输入 meta-action、visual tokens、ego-status，预测 3 秒的未来路点；Table 3 报告 nuScenes 开环指标。其平均 ADE 0.28 m、平均碰撞率 0.14% 是作者结果；ADE 最好不等于碰撞率最好，也不等于闭环安全已验证。

与 ToolV2X 相关的 Table 7 中，Passive-SV、Retrieve View Only、Full Toolkit 的序列准确率分别为 43.10、44.39、45.42。论文已尝试控制视角池比较主动获取，而非只与前视图比较。Table 8 的 adaptive 延迟为 6.74 秒，是文中设备与设置下的推理统计，不能直接挪作 ToolV2X 时延或实时性结论。

**影响：**“Tool + Sequential + Cost + MLP”组合不能自然成为新贡献。需明确远端服务提供什么额外证据、调用前后可知信息如何变化、同等资源下为什么已有获取策略做不好。用小网络替代 RL/VLM 是合理实现选择，但单独不足以支撑创新。

### V2V-GoT：有协同能力参照，但不是开箱即用的远端服务池

正文 III—IV 与 Fig. 3 显示模型融合各 CAV 当前/上一时刻 LiDAR 特征，节点间传递文本答案。Q1—Q4 是 notable-object 感知，Q5 是基于感知的预测，Q6 引入其他 CAV 的计划，Q7 合并预测，Q8/Q9 给动作和轨迹。[论文](https://arxiv.org/abs/2509.18053)

三个直接限制：

1. Q9 仍能获得多车视觉特征。只在文本上删去工具结果，不能建立真正的 Ego-only 或未获取远端证据条件。
2. Q7 包含 Q6 的伙伴计划信息。把 Q5—Q7 一并称为 M，会把原方案“以后再加”的 Partner Plan 工具提前混入预测工具。
3. 原生输出不能直接等同于方案里的带持久 ID、速度、置信度和 K 条概率轨迹的 JSON 服务。已有 QA 与所需工具接口之间仍有实质工作。

Table II 的完整、简化感知、简化预测图通信量均为 0.4068 MB。简化图降低问答节点数不自动减少特征通信；其中简化感知图还重新训练了模型。因此这些消融不能作为冻结模型上四种工具路径的反事实矩阵。

### Select2Drive：显式依赖已有规划的请求也有先例

Section IV-B Eq. 22 用上一轮规划中的路点构造高斯请求区域；DPP 预测接收时刻附近的热图并补偿特征，Algorithm 1 按请求图打包、发送、融合再规划。[论文](https://arxiv.org/abs/2501.12040)

因此，不能把现有 V2X 统一写成仅按感知置信度通信。该文已有规划相关请求、预测计算与时延建模。CoDriving 的 driving-oriented communication 也是必须比较的近邻。

仍可区分的是：这些内容主要是请求和传输表示、补偿与融合；不是本轮已证明存在的、按前次返回结果在异质远端服务之间做下一步选择。这个区分要落在具体输入与控制变量上。

其 Table III 车辆时间包含按算力缩放的估算，Section V 还使用通信模型。复用评价思路时应分别披露实测推理时间和模拟传输时间，不能称为全部车端实测。

### EDDI：序贯获取属于已有问题框架

EDDI 根据当前已观测变量选择下一变量，以目标变量的预期信息增益排序；获得结果后更新观测集，持续到停止条件。Partial VAE 用于任意部分观测的推断。Algorithm 1 已体现结果依赖的查询循环，并有随机与固定顺序对照。[论文](https://proceedings.mlr.press/v97/ma19c.html)

它与 ToolV2X 的目标和对象并不相同：目标熵减少不等于规划损失下降，数值特征也不等于带内部计算的远端服务。但是“序贯、观察后决定、付费获取”不能作为 ToolV2X 的首次性表述。DiFA 进一步表明动态获取并非必须用 RL。

## 四、原方案还需修正的三个逻辑问题

### 单步增益停止会漏掉信息的后续价值

原方案以 `L0 − LP − cost(P)` 决定是否先调用 P。但 P 可能没有直接改善轨迹，却能发现目标并帮助选择 M。

一个仅作逻辑说明的例子：`L0=10，LP=10，LPM=2，cost(P)=cost(M)=1`，并且 M 必须通过 P 才能发现目标。单步规则看到 P 净收益 −1 就停止；两步路径的总目标为 4，明显优于停止的 10。

最多两次调用时，可以用有限深度回推评估继续价值，无需因此引入复杂 RL：

\[
J^*(s,b)=\min\left\{\mathbb E[L_{stop}\mid s],\ \min_{m\in\mathcal A(s,b)}\big[c_m(s)+\mathbb E[J^*(F(s,e_m),b-1)\mid s,m]\big]\right\}.
\]

这里的期待值只能基于当前可用信息；离线 GT 可以产生训练目标，不能让部署策略提前知道返回结果。此式是标准决策思想在当前问题上的表述，不单列为新理论贡献。

### PM 优于 P，不足以证明序贯决策价值

真正需要比较的是：固定相同初始状态特征与预算，用 `s0` 选择下一步，和用 `s0 + eP` 选择下一步，两者在未见驾驶序列上的实际规划—成本表现。

如果每个场景 M 都有益，固定 PM 即可；如果 s0 已能识别需求，one-shot 可能足够。两工具方案可以研究“是否继续”，不必强求 MP 或十种工具才能叫序贯，但必须证明前次结果对继续决策有新增价值。

### M 的优势可能来自信息或算力，而非调用策略

若 M 只对 P 已返回的同一状态运行预测，应比较“相同输入＋相同预测器”的 ego 本地预测；若 M 使用远端独有历史，应比较“同样历史传给 ego 后预测”。后者新增的传输成本也需计入，不能免费赠送历史。

远端计算委托本身可以有价值；但要明确论文证据支持的是计算委托、信息获取，还是结果驱动的序贯选择。把三者混在一起会让控制器收益无法解释。

## 五、建议的最低成本验证顺序

以下是阶段 A 的可回答性建议，不是已执行或已正式冻结的阶段 C 实验。

|顺序|需要获得的证据|继续条件|不满足时的处理|
|---|---|---|---|
|G0：输入契约|从样本到模型输入，逐字段确认截止时间、来源、目标 ID、远端可见性|所有部署输入因果可用；未调用工具无远端结果旁路|修正接口/数据生成后再比较，不报告旧 oracle 为在线上界|
|G1：能力增量|在同一接收器、同一场景上比较 STOP、P、合法的 M、PM；加入 P+本地预测和信息等价对照|M 的有效增量不是仅由额外信息、额外模型或随机噪声解释|只支持 P 时收缩问题；不能硬保留序贯贡献|
|G2：结果依赖|比较同容量 `s0` 与 `s0+eP` 选择器、简单规则、固定级联和 one-shot|同预算下存在跨序列稳定优势|无优势则序贯主张不成立；路由方向另行判断|
|G3：实际效用|统计规划损失、恶化比例、请求响应字节、服务内部执行、端到端延迟|形成有意义的质量—成本改进|只省调用但总成本不降，不能宣称高效远端获取|

评估约束：

- oracle 标签及控制器训练在训练划分产生；阈值/成本权重在验证划分选择；测试只做最终评价。独立单位优先采用驾驶序列，不能把相邻帧视为独立样本。
- 配对结果使用相同场景、模型版本与输入规则；随机生成需要多次评估，防止单次最小损失形成虚假 oracle 优势。
- 简单规则至少包含规划冲突区域、目标到达冲突区时间/不确定性之类的低维特征；这些特征须在各自决策阶段可得。
- 同时报告平均收益和每场景恶化；平均轨迹误差降低不等于所有场景更安全。
- 成本向量先分别报告字节、时间、推理次数，再做权重扫描或预算约束；统一加权时要声明量纲和归一化。
- 序贯等待可能使信息过期。冻结时刻回放能证明信息获取价值，但在线效率还需计入请求、计算、返回和重规划的时间推进。
- M-only 若依赖尚未知晓的目标 ID，则不是合法动作。ROI 型 M 若内部先检测/跟踪，应明确它是复合服务并计入全部工作。

最先该做的是 G0 的实际样本核查，随后固定 P/M/接收器接口。当前不建议直接用原 Q1—Q9 文本缓存训练控制器。

## 六、补充检索与新颖性边界

本轮在 18 篇之外做了有限的定向检索，发现以下应在最终 Related Work 中进一步核查的方向；未新增全文精读或实验结论：

- [Decentralized cooperative perception for autonomous vehicles: Learning to value the unknown](https://arxiv.org/abs/2301.01250)：主动向伙伴请求区域信息。仅“远端主动请求”不能视为全新。
- [Asking for Information by Evaluating the Communication and Coordination Trade-Off in Multi-Agent POMDPs](https://doi.org/10.1109/LRA.2026.3703246)：按信息价值与通信成本决定是否询问其他 agent。远端 VOI 也已有理论近邻。
- [Sequential Task Assignment and Resource Allocation in V2X-Enabled Mobile Edge Computing](https://arxiv.org/abs/2503.20256)：列入任务卸载边界的待核查项，不据标题判定与规划工具获取同题。
- [CooperDrive](https://arxiv.org/abs/2604.14454)：较新的协同驾驶决策工作，保留待进一步正文比较。

有限检索没有建立“首个远端能力获取方法”的证据。也没有证据足以断言 ToolV2X 完全不可做。
