# 驾驶端解码对照的实现约定

日期：2026-09-11。承接已说明并获继续授权的初始化 × 解码方式对照。MTR 稳定性实验运行期间，先补齐这项独立接口工作。

- 默认保留 `q8_q9`：实际生成 Q8，再由该回答构造 Q9。新增显式 `direct` 模式，对应 `Trajectory` 提示，直接生成相同 0.5–3 秒的六点轨迹。未知模式报错，direct 禁止带入 Q8 父回答。
- 两种模式调用相同 `fit_evidence`、同一个 4096 token 上限和既有 Q8 父回答预算余量，保证同一动作的候选证据被相同规则筛选。直接解码暂不利用额外空间增加目标，以避免把目标覆盖变化混入解码比较；实际输入/输出 token 和调用次数如实记录。
- 结果显式记录 `decoding`、`q8_executed`，沿用已有轨迹原文和六点解析字段。默认旧记录按 q8_q9 解释，不能通过缺失父回答自动降级为 direct。
- 离线 SFT 中，direct 只有轨迹回答监督；Q8→Q9 保留真实生成的父回答规则。标签仍单独保存，仅回答 token 参与损失。
- 评价对 direct 的 Q8 指标标记不适用，不把未执行 Q8 计为分类失败。轨迹失败仍留在全部尝试分母中。两阶段父回答缺失继续报错，禁止把旧失败改标签后算成直接解码成功。
- `inputs.py`、`v2vgot.py`、`run_connection.py`、`adaptation_data.py` 与 `evaluation/planning.py` 复用现有代码；测试覆盖单次生成、两模式相同证据、GT Q8 不进入直接提示、旧链条约束及失败分母。
- 为两种初始化使用每个运行目录内的独立本地 adapter 包装目录，链接到明确的已下载权重；原默认目录冲突保护保留，不覆盖另一候选的链接或原检查点。
- 包装目录只决定存放位置。原加载器依赖名称中的 `llava`/`lora` 选择分支；本接口已明确固定原 LLaVA + LoRA 类型，不能让任意目录名改变所选模型类。原生诊断中已观察到目录名不含 llava 会误入 AutoModel 分支，修复后用同一目录重跑真实加载。
- 这是解码入口及评价支持；实际 2×2 选型仍须在冻结 MTR、相同训练数据与可比适配预算下执行。接口检查或原权重零样本结果不能作为骨干优劣结论。
