# 驾驶接收端创新候选：让远端预测表达它改变了什么决策

日期：2026-09-12。性质：独立方法设计与强评审；只有候选，没有新实验结果。保留当前 GoT/MTR、两车、time-t 输入与 direct 六点输出，不改动正在运行的共享驾驶训练。本轮采用 research[B]-idea 的可实现性与引用核验原则，按用户本次明确范围输出独立建议，不推进正式阶段或扩大实现。

## 结论

**目前没有足够证据推荐一个已清楚独立成立的接收端核心创新。** 最多保留一个支撑整体方法的候选：在固定证据容量下，保留“同一远端预测模态如何改变不同自车候选之间的比较”，再交给原 GoT 生成轨迹。候选效用比较已被 TIP 覆盖，有符号两两差只是这种比较的重参数化；不能单独算新点。若整体机制采用可细化的远端消息，这种表示可作为接收支撑，但“TIP + token 压缩”仍不足以自动成立为创新。

这个候选仍有强替代解释：**普通的数值预测 adapter 可能已经解决当前文本表示的主要问题。** 若同信息、同 token、同参数量的普通 adapter 达到相同效果，专门的决策比较结构应降为实现细节，不能继续包装成核心创新。

## 一、当前真正的模型困难

1. **我们保留了数值，不等于模型使用了数值关系。** 当前远端对象按锚点距离进入有限文本容量；每对象六模态六点及分数写进 compact JSON，再由语言模型自己理解数值、模式互斥和对自车的影响。现有代码没有学习到的数值证据融合器。距离近的对象可能对“继续还是减速”没有区分作用，较远的交叉运动对象反而可能改变比较；这只是待验证的数据现象，不能先当实验结论。[容量选择](/root/autodl-tmp/ToolV2X/src/planning/context.py:18)、[source-separated 文本输入](/root/autodl-tmp/ToolV2X/src/planning/inputs.py:171)。

2. **六个 scores 不能直接当完整、校准的未来概率。** 原 MTR 先对全部 queries 做 softmax，再经 NMS 取六条轨迹及其原分数；NMS 不汇总被抑制轨迹的质量，也不重新归一化。它们是供模型使用的置信权重及其截断语义，不能直接用于宣称“碰撞概率为多少”。编码应保留每模态原分数、截取状态和显式 unknown；未保留分数之和也不是已校准的“其他危险未来概率”。跨度大的低分模态只是预测器的假设，不能因几何上冲突便当作可信未来或有效决策歧义。各对象的第 k 模态也没有跨对象联合情景的含义；不同来源对同一对象的预测更不能直接概率相乘。[MTR 输出](/root/autodl-tmp/ToolV2X/vendor/cmp_mtr/mtr/models_v2v4real/motion_decoder/mtr_decoder.py:487)、[NMS 返回原分数](/root/autodl-tmp/ToolV2X/vendor/cmp_mtr/mtr/utils/motion_utils.py:43)。

3. **full P 与 F 的计算等价仍然成立。** 新接收器不能通过名称、重复证据或不同截断方式制造 F 的虚假能力增益。若输入的历史、预测、时间、对象集合完全相同，P 本地计算与 F 交付在接收端应表示同样的预测证据；P 独有的历史仍可作为额外信息单列。不能因此要求“完整 P 所有信息”和“只含 F 的报文”在任何场景都产生完全相同答案。[现有 P 本地重算与来源字段](/root/autodl-tmp/ToolV2X/src/tools/vehicle.py:162)。

## 二、最新近邻已经覆盖什么

| 第一手来源 | 已有内容 | 本项目不能再当作新点的说法 |
| --- | --- | --- |
| [DriveAgent-R1，ICLR 2026](https://arxiv.org/abs/2507.20879v3) | 主动取证、文本/工具模式、分阶段能力与选择训练 | 按需工具、取证后更新推理、成本感知选择 |
| [V2V-GoT，ICRA 2026](https://arxiv.org/abs/2509.18053v4)；[V2V-LLM，ICRA 2026](https://arxiv.org/abs/2502.09980v4) | 协作特征进入 MLLM；GoT 含规划相关预测与多节点推理 | 融合两车信息；把预测用于规划；增加一个推理节点 |
| [TOKEN，CoRL 2024](https://arxiv.org/abs/2407.00959) | 利用原驾驶模型产生对象级知识表示，并做表示/推理对齐 | 用原模型输出做 object tokens，再通过 projector 接 LLM |
| [TIP，IROS 2022](https://arxiv.org/abs/2110.08750) | 通过候选效用比较训练有限加权未来样本，服务下游决策 | 任务相关多模态预测、近似充分统计、比较候选效用；两两有符号差也不能单独创新 |
| [CAPO，ICRA 2022](https://arxiv.org/abs/2204.13319) | attention 或替换预测后的控制变化，用于规划相关预测训练 | 按对自车影响加权对象或预测损失 |
| [COMPACT-VA，RA-L 2026，v3](https://arxiv.org/html/2606.07464v3) | 历史/学习驾驶意图条件化的 token 压缩；训练期未来 posterior 对齐在线 observation prior；同 token 预算比较 | 规划意图引导压缩、辅助未来监督、有限容量保留决策信息 |
| [Defer to Plan，2026-07 预印本](https://arxiv.org/abs/2607.19774) | 在规划端用 autoregressive attention 融合协作 tokens，含 MoE tokenizer | 把融合推迟到规划端、动态权重、MoE 接收器 |

上表足以否定宽泛新颖性表述。剩余可探查空间需要落到远端服务特有的联合约束：**只有已购消息可见，后续消息可细化现有模式而不重复计证据，来源/模式关系可追溯，且固定接收容量下保留必要决策关系**。这仍可能只是已有思想的组合，必须和 TIP 风格效用筛选 + 普通压缩 + 一次性消息交付组成的强对照比较。仅把 COMPACT-VA 输入换成邻车预测，或把单来源变成多来源，均不够。

另需与 [PiP](https://arxiv.org/abs/2003.11476) 等规划条件化预测、[ProDrive](https://arxiv.org/abs/2604.25329) 等候选计划—环境共同推演区分：冻结 MTR 的输出并不随我们的自车探查轨迹重新预测邻车行为，因此下面得到的是“固定预测下的几何暴露差”，不是“我这样开会导致对方那样开”的因果反事实。

## 三、候选 A：保留决策比较关系的多模态证据接收器

### 它想解决的具体问题

一个对象的“重要性”或总风险不能回答：它支持减速、继续，还是两者都不支持；两个未来模态可能对同一比较给出相反证据。只按对象距离、top-1 模态或单个加权风险筛选，可能保留很多数值却丢掉这一差别。候选在压缩前显式组织这种关系，并用训练约束压缩后仍可恢复，而不是期望小样本 SFT 从长串小数里自行发现它。

**这是一项拟验证的表示约束，不是已证明的新概念：有限 token 下，一个模态对不同本车候选的比较关系不应在进入任务模型前任意丢失。** TIP 已有候选效用与有限预测样本框架，因此单独使用这种关系不能作为原创性依据。这也并非普遍必要性定理；如果任务只依赖可分离的期望代价，相应的均值本来就可能足够。只有联合远端可细化协议时出现普通效用筛选/压缩不能解释的独立收益，才有进一步论证方法贡献的理由。

### 最小 pipeline

**第一步：从本车已有状态产生少量“探查轨迹”。** 输入仅含当前速度、历史位姿/曲率和可用本车特征；首个小规模探查可以固定为沿同一因果估计路径的继续、温和减速、较强减速三种时间安排。输出不是新的最终规划器，也不声称这些曲线满足地图/车道规则。若后续使用 GoT 的一条本车草案作为参考，必须给全部对照相同草案，并计入额外一次 GoT 推理，不能隐藏成本。当前无须为此另训练候选生成网络。

**第二步：逐对象、逐模态计算其对探查轨迹的几何关系。** 输入是已经收到的 P 本地 MTR 或 F 预测、原 scores 和当前 box；输出包含每条探查轨迹与该模态的时序接近关系、相对速度、接近出现的时段，以及“相较继续，减速使这种接近增大还是减小”。同一个模态贯穿不同候选，不能先将六条轨迹平均。另保留绝对接近程度：如果所有候选都危险，仅看差值会误认为该对象无关。此处的几何量是输入特征，不是校准风险概率、可执行安全判据或真实避碰标签。

**第三步：小型数值编码器生成证据 tokens。** 输入为原始模式数据及上述关系；先编码每个模态，再在对象内做受约束压缩，最后产生固定数量的远端 tokens。保留来源、对象、模态和未完整覆盖的分数语义，不把不同来源的冲突融合成一条平均轨迹。用一个小投影层把它们送入原 GoT 的文本嵌入空间；原点云 projector 和最终六点文本输出继续复用。首版优先保留对象内六个模式槽，避免另加复杂动态 mode pruning。MLP、attention、projector 都是实现材料，不独立记为创新。

**第四步：一次原 GoT 生成最终六点轨迹。** 输入是原本车点云/文字块加已购买的远端证据 tokens；输出仍是当前任务的单条三秒轨迹，不另接优化器、世界模型或闭环控制器。与当前文本路径的真实差异集中在证据编码，不借“换整个规划头”获得不清楚的增益。[原模型特征投影接入位置](/root/autodl-tmp/ToolV2X/vendor/v2vgot_llava/llava/model/llava_arch.py:434)、[当前监督前向](/root/autodl-tmp/ToolV2X/src/planning/train_driver.py:55)。

### 训练监督与因果性

- **最终任务监督**继续用训练录制组的真实 ego 未来轨迹，保持 answer-only CE；不修改 MTR。普通 adapter 对照必须得到相同训练行、驾驶初始化和更新预算。[当前标签屏蔽](/root/autodl-tmp/ToolV2X/src/planning/adaptation_data.py:112)。
- **关系保持辅助监督**从训练帧的冻结 MTR 输入/输出直接计算：让压缩后的证据恢复逐模式的候选比较方向与接近时段，防止关系信息在瓶颈处被抹去。这类目标不需要未来 GT，但只能证明保存了预测关系，不能证明这些预测为真。
- **必要的等价性检查**包括对象/模式重排、同一预测经 P_local/F 两种交付表示等；它们不能改变语义。若某模式复制并拆分其权重，编码也不应靠重复次数变得更确信。可以先作为检查，不急于多加一项训练损失。
- **不要伪造反事实监督。** 给同一帧人为换掉邻车未来，却继续指定原 ego 轨迹为正确输出，无法证明学会因果响应；只有信息等价的表示变换可以自然复用标签。现有单条记录也不给所有未选择自车动作的真实收益。

### 额外推理代价

采用因果运动学探查轨迹时，新增的是少量逐对象/模态/时刻几何运算和小编码器；最终 GoT 仍只生成一次，不需要增加 MTR 调用或多轮 LLM。其毫秒代价尚未测量，不能预先称实时。数值 tokens 可能比小数文本短，但这项收益必须对比**直接编码原始六模态的普通 adapter**，否则只是证明数值比 JSON 容易压缩。若采用一条 GoT 草案做参考，则明确变成两次 GoT 生成，不再称单次。

### 最小决定性对照与放弃条件

| 对照 | 要排除什么 |
| --- | --- |
| 现有 source-separated compact text，容量与训练预算固定 | 接收器是否实际改善当前路径 |
| 原始六模态、scores、history → 普通小数值 adapter，使用相同来源信息、token 数、参数量与训练更新 | 是否只是摆脱小数文本和容纳更多对象 |
| 同一关系编码但先 top-1/均值化；以及保留六模式但不加关系保持监督 | 是比较关系有作用，还是普通多模态输入/辅助学习普遍有益 |
| 同输入的便宜几何候选评分器作为诊断 | 模型是否只是复述手工几何打分，GoT 是否添加了任务价值 |

这些对照不需要同时研究查询策略。先固定 F 或完整 P_local，在独立录制组比较 ADE/FDE、生成失败、证据预算；再在预先按 time-t 输入定义的“不同模态使候选比较方向不同”子组检验机制。子组不能用 GT 改善大小筛选，也不能把几何方向一致当成最终规划正确。

以下任一结果都应收缩或放弃主张：普通 adapter 打平；收益仅由多保留对象导致且同对象后消失；关系辅助任务学得很好但真实生成无改善；关键子组在现有数据中极少；只在某个手工距离阈值/探查速度设置有效；几何候选评分器达到同样任务质量。尤其当前记录多为既定驾驶行为，未必提供足够“同一局部状态下应因邻车证据改变决策”的学习信号，不能用增加模块弥补任务不敏感。

## 四、候选 B：来源冲突驱动的残差修正——暂不推荐为主贡献

一种直接想法是学 ego/peer 的可信度，只在远端更可靠时对 GoT 输出做残差修正。优点是易接入、单次推理；但当前来源匹配主要靠几何、MTR 模式分数未校准，已有单条 ego GT 很难区分“远端错了”“模型没理解”和“该帧不需要协作”。普通门控 adapter/回归器可完成相近操作，[CAPO](https://arxiv.org/abs/2204.13319) 与 [Defer to Plan](https://arxiv.org/abs/2607.19774) 又覆盖相邻的任务影响/规划融合逻辑。若只用配对误差训练一个 gate，仍接近 generic selector。

因此不建议同时做来源置信网络、模式修正网络、规划残差头三个模块。保留来源身份和不盲目平均，是候选 A 的实现约束；只有后续发现可重复、可观测、跨录制组稳定的来源冲突现象，才重新考虑是否有独立研究问题。

## 五、给主方案的组合建议

推荐坚持一个核心加必要支撑，但核心暂不能仅写“什么证据区分自车决策”，因为 TIP 已覆盖这一原则。**接收端的逐模式关系保持表示仅作为整体远端获取机制的支撑候选**；若查询协议采用相同关系单位做非冗余细化，需要证明获取与接收之间的联合设计优于“普通任务相关筛选 + 普通 adapter”。尤其应比较相同最终消息集合的一次性交付，不能把任何多轮调用都当独立收益。

最先需要的是少量真实帧的可解释验证设计和普通数值 adapter 强基线，不是同时落地上文全部模块。当前证据仅支持候选探查，没有确认它达到 CCF-B/C 的创新强度；最新 COMPACT-VA/TIP/CAPO 的存在要求我们用决定性对照证明那个更窄的差异。无论最终选择哪条机制，都不影响当前已授权共享驾驶训练继续。
