# ToolV2X：结构化协同规划器设计建议

日期：2026-09-14。状态：**供审阅的架构设计，尚未实现、训练或评价**。

本设计承接 [协作驾驶基础复核](cooperative_driving_foundation_review_2026_09_14.md) 和用户最新许可：GoT 可以替换，也可采用合理组合方案。不是重新增加一套远端调用机制。9-12-1/9-12-2 的 P/F、因果、真实反馈和公平控制保留；仅解除驾驶模型必须是 GoT 的绑定。

9-14-1 后续复核：实施前先以 [能力语义与审查回复](review_9_14_1_response.md) 第 3 节约束本设计。P 是任务条件化的因果跟踪状态检索；F 是完整私有上下文预测后的任务检索，不是 ego-plan 条件反应预测。合法缓存可复用。关联/融合为共同返回值处理基础，不能取代反馈调用的研究贡献；本补充不改变运行协议或自动启动实现。

## 1. 推荐与选择依据

**下一版主候选采用“本车检测场景特征＋跨源实体关联＋P/F 分型编码＋共享数值规划器”。GoT 保留为旧基线和备用路线，不放在新主链的必经位置。**

这里的“数值规划器”是完整、可监督的场景交互网络，不是历史上用于试探的恒速/岭回归模型。网络需要同时处理场景、位置、历史、缺失、多源预测及驾驶修订。标准编码器与轨迹头是基础，不计为 ToolV2X 的创新。

| 路线 | 优点 | 主要代价和判断 |
|---|---|---|
| **结构化协同规划器，推荐** | P/F 数值直接入模；坐标损失直接监督；可做字段干预和相同证据迭代 | 需训练驾驶端，且不能凭模型名称补足道路/任务信息；先建立完整接口再评价 |
| GoT＋数值 P/F 编码＋轨迹头 | 可尝试保留已有多模态表示和语言能力 | 额外需要语言空间适配；现有 LoRA 不等于新接口已学会；必须证明 GoT 对输出有作用 |
| 整套迁移 UniV2X / VAD / CoDriving | 可继承其更完整的感知、地图或执行体系 | 各自数据与任务条件不同；应在需要相应任务时迁移，不能把未知/缺失条件置零后冒充完整框架 |

不先实现两条新驾驶路线，也不默认建立“GoT 高层决策＋另一规划器执行”的双驾驶器。后者需要新的高层监督和归因对照，目前没有证据说明这层必要。

选择数值路线是基于接口与可检验性的工程判断，**不是已经证明它优于 GoT**。将来若语言任务、规则理解或合法导航条件让 GoT 显示独立价值，再恢复其作为驾驶组件；已有代码、权重和结果保留。

## 2. 本轮新增核对，以及能借到什么

在上一轮 20 项工作基础上，定向核对 PlanT、PlanT 2.0 与 ThinkTwice，并重读 VAD/UniV2X 的关键接口。下表是设计依据，不表示在本机复现这些模型。

| 参考 | 有依据的借鉴 | 不直接照搬 |
|---|---|---|
| [VAD §3.2–3.4](https://arxiv.org/html/2303.12077v3#S3.SS2) | ego query 与 agent/map query 交互、数值 waypoint 输出、可微轨迹监督 | 原相机/地图/预测全栈；其 motion vectors 也用于训练约束，不能声称论文现成提供了本项目 F 入模接口 |
| [UniV2X §3.4](https://arxiv.org/html/2404.00717v2#S3.SS4) | 对齐后匹配、匹配项融合、未匹配项保留、自车识别 | 直接复用物理 ID、旋转未知语义特征、将近原点目标一律删除；论文也指出定位误差限制 |
| [PlanT](https://arxiv.org/html/2210.14222) | 对象数值表示、标准 Transformer 和驾驶头可构成研究用规划基础 | 其路线输入和主要实验的模拟器对象真值；本项目必须用因果检测/跟踪输入 |
| [PlanT 2.0 §3、§5](https://arxiv.org/html/2511.07292v1#S3) | 每个输出点的 token、结构化输入干预诊断；重视道路与对象类型完整性 | 它使用额外对象类别和道路表示；即使完整训练，仍发现捷径和泛化问题，不能视为“换成 Transformer 就解决” |
| [ThinkTwice §3.2](https://arxiv.org/html/2305.06242#S3.SS2) | 已有方案作为条件检索信息并作数值修订；支持有意义的相同证据迭代对照 | BEV 未来预测、世界模型和原训练中的额外 GT 条件，不引入新预测骨干 |
| 本地 CMP/MTR 源码 | `PointNetPolylineEncoder` 的带 mask 折线编码；当前冻结 MTR 的预测能力 | 完整 CMP aggregator 依赖共同目标组织和上下文，不是现成实体关联器或 ego planner |

新规划器是上述标准部件思想的组合和本地接口适配，不命名为 VAD/PlanT/UniV2X 复现。哪些代码原样复用、哪些按论文重新实现，必须在实现记录中区分。

本轮确认 UniV2X、VAD、Driving-with-LLMs、LMDrive、Co-MTP 的建议本地目录仍不存在。VAD 官方代码文件网页访问失败，未宣称完成其逐函数审查，也未绕过用户下载分工。

## 3. 锁定实际任务，防止新架构掩盖旧口径问题

首版任务为：在固定物理时刻 t，基于本车当前/历史观测和实际购买的 P/F，输出 ego(t) 坐标系下 0.5、1、1.5、2、2.5、3 秒的六点轨迹。当前标签是记录中的本车实际未来，因而结果首先是**开环短时轨迹模仿/规划评价**。

| 数据 | 本轮确认的现状 | 新路线处理 |
|---|---|---|
| 本车检测场景图 | `load_ego_features()` 读取 14 通道 regression、2 通道 classification，两帧各 50×88 | 保留本车输入；按原 5×4 patch 分块后做普通数值投影 |
| 缓存覆盖 | 两个 `no_fusion_keep_all/npy/co_llm/ego` 目录仅这两种图和 `detection_box_score`；物理 train/test 各种文件分别 7105/1993 份 | 这是目录清点，不是研究 split 或逐帧内容验证；没有确认可直接使用的深层 BEV 缓存 |
| 本车历史 | `local_window` 已有 11 个因果跟踪状态；`new_ledger()` 当前只写 anchor/forecast | 新账本明确增加本车 history；不能期待新编码器从旧账本凭空恢复 |
| 本车运动 | 当前输入显式含 speed、yaw_rate，来自 t/t−1 定位 | 复用并保持缺失 mask，不从未来反推状态或转向指令 |
| 道路/导航 | 当前入口没有合法 route command、道路边界或交通规则字段 | 首版明确缺失；不把检测头图称作语义地图或可行驶区域 |
| 自车标签 | `adaptation_data.ego_label()` 从未来定位生成六点标签 | 复用未按文本格式舍入的数值标签，只在训练/离线评价加载 |

本车历史图属于各自的采集帧。新编码器若把 patch 位置当作米制空间位置，必须随输入携带相应格点几何和采集帧到 ego(t) 的变换；仅拼接 t/t−1 的图不等于已对齐。首版沿用原 patch 网格索引/时间标签，不将它用于米制 ROI 采样或道路距离计算；实体历史仍使用已实现的固定 ego(t) 坐标。后续引入空间采样时再补对应标定规格。

道路/导航缺失是完整驾驶任务的实质限制。它不阻塞建立当前受限任务的完整驾驶链，但不能一直留到论文结论里含糊处理：若需要声称路线执行、越界减少或闭环安全，就先接入有合法任务条件和标签的评价设置。不能从真实未来取转向命令补在线输入。

## 4. 完整信息流与共享驾驶器

```text
本车场景图、运动、历史、冻结 MTR 的本车预测
                    |
          共同实体表示 Z0 → 同一 D → tau0
                                      |
                             P/F(current, tau0)
                                      |
                       peer 私有上下文真实执行
                                      |
                         返回字段、receipt → E1
                                      |
                       关联、编码、融合 → Z1
                                      |
                           同一 D(Z1, tau0) → tau1
                                      |
                    用实际 tau0/tau1 选请求或 STOP
                                      |
                     最多一次 P/F(current/change)
                                      |
                         E2 → Z2 → 同一 D → tau2
```

初始 D 也有明确的先前方案槽位，值缺失且 mask 为 false；不伪造一条 GoT 初始计划。D 的编码器、注意力和轨迹头在各轮共享权重。数值修订作为所有方法共有的驾驶接口，不作为新增 Tool 机制。

### 4.1 实体关联与融合

输入只能是本地字段和合法 E/derived 字段，不读取尚未购买的 peer 目标列表。现有 peer 框缓存已经投影到 ego 系；不重复乘车辆相对变换。

关联采用当前几何与共同有效历史残差、尺寸/朝向兼容性门控，以及一对一匹配。源内 track handle 与跨源 entity ID 分开。门控数值放配置；排序和平局规则属于协议。相同源内字段后续更新不得因输入排列改变实体身份。

新实体结构建议为 `EntityRecord(entity_id, aliases, role, association, observations, forecast_sets, parent_refs)`：

- `observations` 保留各源原状态、历史、时间、score、valid；P 仍是 **causal tracking-state motion proxy** 的来源，不是逐帧 detector hit。
- `role` 至少区分 ego 与非 ego/未确定。自车判定结合尺寸、位置、合法历史；近原点距离本身不充分。可靠识别出的 ego 不作为外部障碍。
- `association` 区分匹配、歧义和未匹配；歧义不强行合并。远端独有对象保留，不要求先在本车有对应目标。
- `forecast_sets` 按 source/context 保存整个模式集合；源内第 k 模式不与另一个源的第 k 模式自动对应。
- 标识符、receipt 字符串和请求模式不作为可学习特征；来源角色、实际缺失、上下文范围可以进入数值表示。

实体内先对各源观测编码，再以共享 attention 形成状态表示，属于**特征融合**。展示/几何锚点按确定质量规则选取一个原始 anchor，明确它是代表值；不把检测 score 当成方差，不声称输出了经过校准的融合状态后验。不同机动的未来坐标不能平均成一条“融合轨迹”。

跨源状态信息在可训练表示中融合，但原 E 不修改。这比只按 source/track 拼接文本多了实际融合步骤，也保留错误关联的排查依据。

### 4.2 P 与 F 的独立入模接口

| 通路 | 进入规划器的内容 | 附加计算 |
|---|---|---|
| Ego | 本地历史/anchor、本地完整上下文预测、本车场景图与运动 | 本地冻结 MTR 与共同驾驶器 |
| P-state | 新的当前框、历史、缺失 mask，和本地同实体状态融合 | 不自动触发 receiver MTR |
| P-local | P-state 加上 receiver 使用已获上下文运行 MTR 得到的预测 | 单独记录预测计算和上下文；作为显式处理选项 |
| F | 随包 anchor、六模式六时刻 xy、各模式 score、model_used | provider 完整上下文预测后检索；receiver 不先补一次 MTR |
| PF | 兼容的状态/历史与预测共同进入同一实体 | 不按工具种类复制同一实体；保留不同预测上下文 |

新路线基础的 P 采用 `observations_only`，以区分“收到观测就能利用”和“本地增加预测计算”；P-local 单列。旧 P 的默认行为保持原版本含义。

完整 P 的同信息控制仍保留：源内完整上下文、同模型/顺序/mask/精度的 receiver MTR 与 provider F 对齐。做 driver 同信息比较时，必须再固定实际入模字段和数值表示，不能一边额外含全部历史，一边只含预测，却称驾驶输入相同。

在相同完整来源上下文下，F 与 P-local 的 forecast token 编码应一致；provider 执行还是 receiver 派生的信息留在账本和成本，不通过一个不同的“工具身份 embedding”故意造成输出差异。若把 ego 与 P 混合重算，那是另一上下文，不能用来证明 F 等价。

### 4.3 数值编码与轨迹输出

建议的共同驾驶网络包括四部分：

1. **场景分支**：现有本车 regression/classification 图按原 GoT patch 布局变为向量，加入网格/帧编码，投影到驾驶隐空间。复用数据与分块方式，不要求加载 7B、CLIP 或语言 tokenizer。
2. **观测分支**：每个源的 11 步状态与 mask 经折线编码；位置、尺寸、sin/cos 朝向、score 和相对时间明确归一化。源内时间编码后做实体内融合。
3. **预测分支**：每个模式分别编码未来 xy、相对时间和 mode score，关联实体状态。多个模式仍是独立 token，只有表示交互，不输出一条坐标均值；不宣称当前 wire 携带协方差或校准概率。
4. **规划分支**：六个 waypoint query 与实体状态、预测模式及本车场景交互，再由共享数值头输出六点轨迹。ego 运动和可用的上一实际方案作为条件；第一轮上一方案缺失。可输出相对上一方案的残差，初始化轮使用同一头和缺失标记。

这是 VAD 式 query 规划、折线编码和标准数值修订的组合，**没有把 MTR 改造成新的 ego 预测骨干，也没有训练新的交通参与者预测器**。规划器本身需要新训练，已有 MTR 参数不等于驾驶头初始化已完成。

本地 `vendor/cmp_mtr/mtr/models_v2v4real/utils/polyline_encoder.py` 可参考/复用。其默认 MLP 使用 BatchNorm；短历史、空集合或单有效点的训练输入不能直接假定安全。建议在新驾驶模块中保留其折线聚合方式、使用 LayerNorm 与显式空 token；不改动冻结 MTR 的 vendor 或权重，不声称新编码器仍是原参数原样复用。

所有 padding 由 mask 屏蔽，空集合不能产生 NaN。位置/历史/未来的标准化参数仅用训练数据拟合。训练与推理走同一张量构造函数。

### 4.4 容量、来源与配置

建议用 `StructuredDriverSpec` 保存编码维度、层数、实体/模式集合容量、归一化、上一方案槽位、初始化和输出规格；通过新的 method run 版本完整保存。provider 的 `ExecutionSpec` 继续保存 sigma、max_targets、wire/episode 限额及执行阈值。两者不互相伪装。

首版供实现评估的统一起点为 hidden_dim=256、attention_heads=4、interaction_layers=2、max_entities=64、max_forecast_sets_per_entity=4；这些是可调整的实验设置，不是协议常量或性能承诺。每个合法 forecast set 保留现有六个模式和六个时刻。

实体按已知代表 anchor 距离和稳定字段身份排序；多预测集合按完整上下文优先、已知 parent 数量、稳定身份排序。超限与歧义保留明确记录，不按效果倒选对象。不同方法使用相同容量规则；全本地容量基线另列。实现前对实际合法字段规模核对容量，而不是默认 64 已覆盖所有样本。

Z 不再用文本 token 数衡量。`admission_report` 需记录被选字段、关联使用字段、模式/实体丢弃、张量 mask 和实际依赖闭包。参与匹配、筛选或融合的已购字段即使没形成独立 token，也不能记成“driver 完全没用”。

**上一方案是信息载体。** 若 tau1 依赖 Z1，之后把某字段从 Z2 剔除，但 D 继续接收 tau1，这个字段仍是最终计划的间接来源。`PlanRecord` 必须保存上一 plan ID 和递归 parent refs，不能只检查本轮 tensor manifest 就宣称遗忘该证据。

## 5. 替换 GoT 后，控制实验怎样继续成立

| 控制 | 新路线的具体执行 | 归因边界 |
|---|---|---|
| 固定 Ego/P/F/PF/rule | 旧 GoT 版本原样保留；新共享 D 下重做同名固定策略，并明确 P-state/P-local | 新 driver 与旧 GoT 的差异不是请求机制收益 |
| 固定首轮与真实/冻结反馈 | 分叉同一实际首轮请求、响应、tau1 与模型；只改变第二请求可用的修订方案 | 防止首轮证据或模型差异冒充反馈价值 |
| current/old/union/change | 复用当前确定 service 规格和同规模候选集 | 不能增加 change 候选后只比较更弱固定 ROI |
| exact repeat | 固定 Z、上一方案、模型和全部输入，重复 D | 应确定一致，主要检查确定性；不是充分的额外推理基线 |
| **same-evidence refinement** | 固定同一真实首轮后的 E1/Z1，继续 D(Z1, tau1)；不调用工具、不读取新字段、不扩大 admission | 上一方案可更新，因而是有作用的迭代；共享训练、权重、调用数，并记录实际成本 |
| **strong one-shot conditional delegation** | 复用 bundle 条件程序，在 peer 私有上下文依据首项真实结果决定第二项/STOP；最多两个能力 primitive、一个 RPC | 不是固定 PF，也不允许免费运行 ego 私有状态下的新驾驶方案 |

同证据修订槽位在新主方法与对照中始终存在，不能仅给对照临时加入未经训练的格式。固定 E1/Z1 指张量、模式、关联和来源闭包固定；不得在重复期间从已购但未入模内容重新筛选更多字段。若沿用本地模型缓存，所有方法按相同规则使用并计费。

强单轮的第一方案、上传摘要、候选构造、provider P/F 和 bundle continuation 的训练划分应匹配交替方案；continuation 用自己的合法输入重新获得监督，不拿旧 GoT 的价值标签直接训练新 D。相同总字节限额下，摘要/程序描述、两项结果及 receipt 均收费；一包两项和两包各一项的 envelope 差异据实计入。

为排除计算优势，单轮可以在拿到最终证据后用同一 D 继续数值修订至共同驾驶调用上限。它仍然没有中途回传真实 tau1 的机会。实际远端 primitive、MTR 计算次数、网络往返、driver 调用和耗时分别报告，而不只对齐 RPC 次数。

provider 冻结 MTR 全上下文计算可合法缓存复用，实际执行一次就记一次；缓存从何时建立、哪些上下文可命中必须记录。receiver 编码、关联、计划头、价值模块同样计时。训练成本另表，不混成每次部署延迟。

原来的“三次 GoT 对一次 GoT”变为“三次完整 D 对一次完整 D”。去掉 LLM 可能降低该差额，但**未实测前不给加速倍数或实时结论**。固定 t 的内部修订仍不是闭环行驶。

## 6. 训练组织：先学会共同驾驶，再学请求

本轮不训练。后续不续跑旧文本 CE 检查点来代替新驾驶端适配。

驾驶训练用同一帧对应的合法 Ego、P-state、P-local、F、PF，以及真实阶段证据缺失/容量条件；监督仍是同一条实际 ego 未来。编码器、融合与驾驶头联合训练，MTR 冻结。证据类型比例和预算覆盖写入训练规格，不为了制造 F 增益改轨迹标签。

上一方案必须来自当前/冻结驾驶器的因果前向，或明确的无 GT 初始化，不把真实未来放进上一方案槽。对同证据修订及增量证据修订都展开共享 D；前次输出可按训练规格 detach，逐轮用独立未来标签计算 SmoothL1。初始模型输出异常时不丢掉难例：首轮初始化本来缺省，后续槽位置无效并保存异常原因。

基本损失先用数值轨迹监督；直接可微，不通过字符串解析。道路/碰撞损失只有在标签、坐标、车辆几何和缺失规则可靠后加入。用预测 F 自身构造的冲突罚项只能称预测风险代理，不能同时把同一代理当作独立安全评价。

检查不止看 loss：必须有有效点上的 P/F 梯度、mask/置换检查，以及同帧正确/去除/错配证据的行为诊断。梯度非零说明连接存在，不能证明模型学会利用信息；输出变化也可能是不稳定。实际效用需要独立记录上的配对质量和失败分析。

基础 driver 冻结后，重新采集真实 current/change 分支并产生新价值监督。已有 T7/T8 的分支验证和普通 MLP 结构可复用；旧标签/教师/checkpoint 与 GoT 绑定，不可只改 model_version 后继承。

## 8. 评价与决策标准

先在预声明记录集合报告基础误差、有效率、失败率、P/F 获得/进入模型的覆盖和总成本，再报告机制实验。保留速度-only/恒速参考和完整本地场景基线；它们用于排查捷径，不替代共同驾驶框架。

指标分两套命名：`ADE3` 与 `FDE3` 继续保留；新增明确的官方 GoT 前缀均值 L2@1/2/3s 和三者均值。旧端点 `L2_1/L2_2` 不静默改义。即使数学归约一致，样本、输入、车辆角色和模型不同仍不能与论文直接排名。CMP 的多模态他车预测指标单表。

按预声明交互/转向/减速等场景分组，同时保留全体样本；不能按“F 带来改善”的结果反向挑子集。相关帧按录制组处理统计依赖。检测缓存/预训练来源未明确之处继续披露。

路线后续调整依据：

- 若 P/F 进入数值通路且训练适配完成，仍对合理证据干预不敏感，先定位状态捷径、输入语义和监督覆盖，不能直接加深网络或延长训练。
- 若协作基础有效，但真实修订不优于强单轮/同证据迭代，就不能宣称反馈必要；可收缩 change 的贡献，不人为制造两次调用。
- 若主要问题来自道路/导航缺项，先补对应合法输入与评价，而不是恢复 GoT 并期待语言补出未知环境。
- 只有 GoT 在同信息、同监督、计入计算的比较中提供实质能力，才有充分理由进入新主链。首版不要求为这个可选问题同时训练两套新系统。
