## 预算改动的实际影响

用原 checkpoint tokenizer 对历史验证帧重新选择证据，分别测量 JSON 和 compact；没有重新运行 7B。动作顺序为 Ego / P / F / PF：

| 格式 | 历史保留记录 | 修复后重新选择 |
| --- | --- | --- |
| JSON | 5 / 4 / 5 / 4 | 5 / 3 / 5 / 4 |
| compact | 19 / 9 / 19 / 8 | 18 / 8 / 18 / 8 |

原复现中 P/JSON 的合法 124 token 父回答使 Q9 输入加输出预算达到 4170；修复后同一父回答与重新选择的 3 条记录需要 3726，低于 4096。8 种动作/格式组合的这项检查均未超限。历史计划结果保留原样，不能据此推断新预算下的生成质量。

128 token 余量是选择时的保守估计；生成 token 经解码再编码的长度可能变化，所以实际容量检查仍是最终边界。用于验证残余超限处理的测试额外构造了一个过长父回答，以触发真实 guard；它不是一次自然发生的 128 token 生成，也不代表模型失败率。Q8 原文没有规范化缩写、截断或 GT 回填。

## 训练前仍需明确的语义

无 ROI、完整提供方历史的 P 本地重算才是 F 的同信息对照。P 仅返回 ROI 内历史时，F 仍利用提供方完整上下文，同一输出目标集合不保证输入信息相同。

当前 `history_valid` / 窗口 `valid` 表示可用跟踪输出，包含漏检时 AB3DMOT 维持的因果预测状态。它们不等于当帧检测匹配位；此前真实跟踪器复核见 [本机复核报告](review_9_10_verification.md)。本轮澄清文档和代码说明，未改写有效位或缓存。若后续训练需要检测观测掩码，应先补跟踪导出字段，再生成新版本缓存。
