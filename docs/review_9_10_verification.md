# 9 月 10 日代码审查的本机复核

本轮收到 `docs/9-10.md` 后，先完成只读复核；没有修改生产源码、提交或推送，也没有启动训练。用户提供的两份原报告均保持原样。以下是新执行结果，独立于网页版的测试记录和之前的仓库准备报告。

## 结论

报告中的五项实现问题全部成立。前两项应在下一次批量运行前修复；报文和计算成本字段也需要修正后再用于实验结论。已有 62 项集成测试本轮重新运行仍全部通过，说明这些问题没有被现有测试覆盖，不能据此否认缺陷。

上一轮可迁移性改动只覆盖了统一读取层，漏掉主运行器的直接调用；此前“核心入口可配置”的说明因此不完整。

| 问题 | 本轮复核证据 |
| --- | --- |
| 主运行器绕过配置根目录 | 给统一读取层设置临时目录，拦截实际 `prepare()` 的两个读取入口；二者仍收到旧工作站路径 |
| Q8→Q9 预算和记录丢失 | 使用原 checkpoint 的 SentencePiece tokenizer，构造合法 124 token 的 Q8。固定原型预算为 4065，实际 Q9 输入加 256 输出预算达到 4170，超过 4096；实际 `plan()` 抛出预算异常 |
| 报文相同字段缺乏检查 | 两个合法 P 报文只改过去时刻的历史分数，字节长度均为 1433，内容不同；接收后 evidence 相同。比较入口仍直接写 True |
| 相对 checkpoint 软链接失效 | 临时目录内实际调用 `local_adapter()`；源文件存在、软链接创建成功，但链接 `is_file()` 为 False |
| 回退目标误计为模型计算 | 对两个仅有当前状态的目标调用生产 `cmp_adapter.predict()`；没有调用模型，响应的 `model_used` 均为 False，但服务成本字段报告计算了 2 个模型目标 |

预算复核使用真实 tokenizer 和真实容量检查，但 Q8 是构造输入，没有调用原 7B 生成。这个结果证明逻辑缺陷，不是自然生成失败率；也没有把历史五点 Q9 格式失败归因于此。

## 对历史结果的影响

本轮直接逐字比较了 `framework_connection_v3` 与 `framework_compact_v1` 中四动作对应的 8 个请求/响应存档文件，全部相同。因此这两组历史记录的报文相等可由本轮独立检查支持；需要修的是比较入口不能自行保证该结论。后续修复采用直接字节比较，不采用内容摘要。

相对路径问题在原工作站使用绝对路径时不会触发。成本问题针对 `model_targets_computed`；它不推翻按实际响应字节计算的带宽记录。代码存在这些问题，也不推翻原 MTR、原 projector 和原 LLaVA 已接入的事实。

## 两个研究边界

ROI 边界也得到复核：同一 ROI 返回一个目标，F 的预测器看到提供方两个目标，P 本地重算只看到返回的一个目标。使用上下文敏感的测试预测替身时结果不同。这是输入范围不等价，不能从无 ROI 的完整 P/F 对照外推；本轮没有声称真实 MTR 在该 ROI 上出现了确定的质量差异。

跟踪状态语义比网页版报告更明确了。本轮用**当前实际 AB3DMOT、项目实际配置和坐标转换**输入 11 帧合成检测，在第 5 帧断掉检测：该帧检测数为 0，跟踪器仍输出 1 个目标，`time_since_update=1`；该状态继续进入因果窗口和 P 报文，`history_valid[5]=True`。这里没有未来数据读取，状态来自因果跟踪维持。

因此当前 `history_valid` 表示“该时刻有可用跟踪输出”，不能当作“该时刻有检测匹配”。源码/协议中称其为 observed history 的地方应澄清。若正式 MTR 训练或分析需要观测掩码，应在跟踪导出时另外记录检测匹配状态，再生成新版本缓存；不要改写旧缓存或把这一语义差异误判为未来 GT 泄漏。

## 后续修复顺序

1. 让 `prepare()` 的特征和运动读取统一服从配置，并补入口级回归测试。
2. 在选择证据时为完整 Q8 父回答留出预算；实际 Q9 再核算容量，将预算失败记录成结构化动作结果，保留 Q8 并继续其他动作，不用 GT 回填或静默截断。
3. 对请求/响应存档直接比较字节，缺失时明确未检查；增加“wire 不同但 evidence 相同”的负例。
4. 在创建 adapter 前规范化 checkpoint/CLIP 路径，并验证链接能解析到文件。
5. 按实际 `model_used` 和是否本次计算统计模型目标数，分别记录回退、返回目标和缓存命中。

ROI 上下文声明及跟踪状态/检测观测的语义，应在正式适配训练前处理。它们不要求推倒当前原模型主线，也不构成现在增加 RSU 或确定最终查询机制的理由。
